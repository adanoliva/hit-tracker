## Descripción

Actualmente todos los textos de la app están hardcodeados en español, repartidos en cada componente. Esta feature introduce infraestructura de internacionalización (i18n) con `i18next` + `react-i18next`, migra **todos** los textos visibles al usuario a ficheros de traducción por clave (`es.json` como origen, `en.json` como segundo idioma), y añade una nueva pestaña **Ajustes** en la navegación (después de "Perfiles") donde el usuario puede:

- Seleccionar el idioma de la app (selector con texto "Español" / "English", sin banderas — el proyecto no usa emojis ni iconos de bandera).
- Gestionar la conexión de la cuenta de Google Drive (movida desde la pestaña Perfiles).
- Ver el modal "Acerca de" con la versión de la app (movido desde la pestaña Perfiles).

El idioma seleccionado se persiste en disco (`expo-file-system`, igual que el resto de settings de la app) y se usa como override sobre el idioma del sistema en el arranque siguiente.

## Criterios de aceptación

- [ ] Ningún componente de `src/components/` ni `src/navigation/` contiene strings de texto hardcodeados visibles al usuario — todos pasan por `t('key')`.
- [ ] Existen `src/i18n/locales/es.json` y `src/i18n/locales/en.json` con las mismas claves (misma estructura anidada) en ambos ficheros.
- [ ] Al arrancar la app por primera vez, el idioma por defecto es el del sistema si es `es` o `en`; para cualquier otro idioma del sistema, el fallback es `es`.
- [ ] Existe una pestaña "Ajustes" al final de la barra de navegación inferior (después de "Perfiles"), con su propio icono Lucide.
- [ ] La pestaña Ajustes contiene: selector de idioma, sección de cuenta Google Drive (con el mismo comportamiento — conectar/desconectar/reintentar sync — que tenía en Perfiles), y el modal "Acerca de" (mismo contenido que el actual, accesible desde un botón/fila en Ajustes en vez del icono `ⓘ` flotante).
- [ ] La pestaña Perfiles ya NO contiene la sección de cuenta Google ni el botón/modal "Acerca de".
- [ ] Cambiar el idioma en Ajustes actualiza inmediatamente todos los textos visibles en la app, sin reiniciar.
- [ ] El idioma elegido persiste tras cerrar y reabrir la app.
- [ ] Los tests Jest existentes (`shared/__tests__`, `src/__tests__`) siguen pasando sin modificación (i18n no afecta lógica de negocio pura).

### Lógica de negocio

**Inicialización de idioma** (`src/i18n/index.ts`):
1. Al importar el módulo, llamar a `i18n.use(initReactI18next).init({ resources: { es: { translation: esJson }, en: { translation: enJson } }, lng: undefined, fallbackLng: 'es', interpolation: { escapeValue: false } })`.
2. `lng` inicial: cargar de forma async desde `storage.loadSettings()` en el arranque de `App.tsx` (via `settingsStore.loadSettings()`); si no hay valor guardado, usar `Localization.getLocales()[0]?.languageCode` — si es `'es'` o `'en'` usarlo, si no, `'es'`.
3. `settingsStore.setLanguage(lang)` llama a `i18n.changeLanguage(lang)` (esto re-renderiza todos los componentes que usan `useTranslation()` automáticamente) y luego `storage.saveSettings({ language: lang })`.

**Claves de traducción**: usar namespacing por pantalla/sección para evitar colisiones, ej:
```json
{
  "common": { "cancel": "Cancelar", "save": "Guardar", "delete": "Eliminar" },
  "nav": { "home": "Inicio", "session": "Sesión", "training": "Entrenamiento", "devices": "Dispositivos", "profiles": "Perfiles", "settings": "Ajustes" },
  "settings": {
    "title": "Ajustes",
    "language": "Idioma",
    "googleAccount": "Cuenta Google",
    "about": "Acerca de"
  },
  "dashboard": { ... },
  "session": { ... }
}
```

**Textos con interpolación** (ej. `"${pendingUploads.length} sesiones pendientes"`) deben usar la sintaxis de i18next: clave `"pendingSessions": "{{count}} sesiones pendientes"` y `t('settings.pendingSessions', { count: pendingUploads.length })`. i18next soporta pluralización automática vía `_plural` si se necesita distinguir singular/plural (revisar caso por caso, no todos los textos lo requieren).

**Migración de la sección Google Drive y "Acerca de"**: el comportamiento (conectar, desconectar, reintentar sync, resolver conflictos, mostrar versión desde `app.json`) no cambia — solo se mueve el JSX y los hooks (`useDriveStore`, `connectGoogle`, `disconnectGoogle`, `retryPending`, etc.) de `Profiles/index.tsx` a `Settings/index.tsx`.

## Escenarios de test

1. **Escenario**: cambio de idioma persiste tras reiniciar
   - **Given**: la app está en español por defecto
   - **When**: el usuario selecciona "English" en Ajustes y cierra/reabre la app (simulado recargando `settingsStore` desde `storage.loadSettings()`)
   - **Then**: la app arranca en inglés (`settingsStore.language === 'en'`, `i18n.language === 'en'`)

2. **Escenario**: idioma del sistema no soportado cae a español
   - **Given**: no hay settings guardados (`storage.loadSettings()` devuelve el valor por defecto) y `Localization.getLocales()[0].languageCode` es `'fr'`
   - **When**: se inicializa `settingsStore`/`i18n`
   - **Then**: el idioma resultante es `'es'` (fallback), no `'fr'` ni un crash por idioma no soportado

3. **Escenario**: claves de traducción consistentes entre idiomas
   - **Given**: `es.json` y `en.json` cargados
   - **When**: se comparan recursivamente las claves de ambos objetos
   - **Then**: tienen exactamente el mismo conjunto de claves (test que falla si a alguien se le olvida traducir una key nueva)

## Notas de implementación

- **No** usar banderas ni emojis en el selector de idioma — regla existente del proyecto (CLAUDE.md: "Nunca usar emojis como iconos en la UI"). Selector con texto plano o un `TouchableOpacity`/dropdown estilo el resto de la UI (`StyleSheet`, colores de `theme.ts`).
- El desktop (`desktop/`) está archivado (tag `desktop-freeze`) — esta feature es solo mobile, no tocar `desktop/`.
- Riesgo principal: el volumen de archivos a migrar (20 componentes) hace esta feature grande para una sola pasada de `/dev` — si el agente dev lo considera inabordable en una sesión, puede proponer trabajar por lotes (infraestructura + Settings primero, migración de pantallas después) sin necesidad de crear specs nuevas, ya que los criterios de aceptación de esta spec cubren el resultado final completo.
- Alternativa descartada: librería ligera custom sin i18next — descartada por decisión explícita del usuario a favor de `i18next`/`react-i18next` por ser el estándar del ecosistema RN/Expo y facilitar añadir idiomas futuros (plurales, interpolación, fallback ya resueltos).
