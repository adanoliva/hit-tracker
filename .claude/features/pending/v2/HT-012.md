## Descripción

Durante una sesión de entrenamiento en mobile, el usuario puede activar la grabación de cámara. El vídeo MP4 y los datos del sensor BLE se capturan en paralelo con timestamps sincronizados. Al terminar la sesión, ambos archivos quedan guardados localmente y el detalle de sesión (HT-002) puede mostrar el vídeo junto con los datos de impactos.

## Criterios de aceptación

- [ ] Botón "Grabar" disponible en la pantalla de Training antes de iniciar sesión
- [ ] Al iniciar sesión con grabación activa, el vídeo y los datos BLE empiezan simultáneamente
- [ ] Indicador visual de grabación activa durante la sesión (punto rojo + tiempo)
- [ ] Al finalizar la sesión, el vídeo MP4 se guarda en `<documentDirectory>/HitTracker/videos/`
- [ ] El `Training` persiste `videoPath` (ruta al MP4) y `videoStartTime` (timestamp ms)
- [ ] `SessionDetail` (HT-002) muestra el vídeo si `training.videoPath` existe
- [ ] Si BLE se desconecta durante grabación, el vídeo continúa y se muestra aviso
- [ ] Si la cámara no tiene permisos, el botón "Grabar" queda deshabilitado con mensaje explicativo
- [ ] Sin grabación activa, el comportamiento es idéntico al actual (sin regresión)

### Tipos modificados

```ts
// shared/types/index.ts — campos opcionales, sin romper compatibilidad
interface Training {
  // ... campos existentes ...
  videoPath?: string       // ruta local al MP4, undefined si no se grabó
  videoStartTime?: number  // timestamp ms del inicio del vídeo (para sync)
}
```

### Lógica de negocio

#### `useVideoRecording`

```ts
function useVideoRecording(): {
  isAvailable: boolean        // permisos concedidos y cámara disponible
  isRecording: boolean
  startRecording(): Promise<void>
  stopRecording(): Promise<{ uri: string } | null>
}
```

- `startRecording`: arranca la grabación y registra `videoStartTime = Date.now()`
- `stopRecording`: finaliza, copia el vídeo a `<documentDirectory>/HitTracker/videos/<trainingId>.mp4`, devuelve la ruta
- La sincronización sensor↔vídeo se calcula con `impact.time - videoStartTime` (ms desde inicio del vídeo)

#### Flujo en Training

1. Usuario activa toggle "Grabar" → `useVideoRecording.startRecording()`
2. Se inicia la sesión normalmente (`useTraining.startTraining(...)`)
3. Al finalizar la sesión → `useVideoRecording.stopRecording()` → obtiene `uri`
4. Se añade `videoPath` y `videoStartTime` al `Training` antes de guardarlo

#### Reproducción en SessionDetail

- Si `training.videoPath` existe → mostrar reproductor de vídeo encima del gráfico del round activo
- El reproductor debe ser compacto (no pantalla completa por defecto)
- Sin sincronización automática vídeo↔marcadores en esta versión (MVP)

### Permisos Android

```xml
<!-- AndroidManifest.xml -->
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

Solicitar permisos en tiempo de ejecución con `expo-camera` antes de mostrar el botón activo.

### Almacenamiento

```
<documentDirectory>/HitTracker/
└─ videos/
   └─ <trainingId>.mp4
```

Los vídeos no se sincronizan con la nube (fuera de scope). La eliminación de una sesión (HT-002) también borra el vídeo si existe.

## Escenarios de test

1. **`useVideoRecording` — sin permisos**
   - Given: permisos de cámara denegados
   - When: se monta el hook
   - Then: `isAvailable === false`

2. **`videoPath` se persiste en Training**
   - Given: sesión finalizada con grabación activa
   - When: se carga el Training desde disco
   - Then: `training.videoPath` es una ruta válida al MP4

3. **sin grabación — Training sin videoPath**
   - Given: sesión finalizada sin activar grabación
   - When: se accede a `training.videoPath`
   - Then: es `undefined` (sin regresión en el modelo)

4. **sincronización timestamps**
   - Given: `videoStartTime = 1000000`, un impact con `time = 1005000`
   - When: se calcula `impact.time - videoStartTime`
   - Then: resultado = `5000` ms (5 segundos desde el inicio del vídeo)

5. **BLE desconectado durante grabación**
   - Given: grabación activa, BLE se desconecta
   - When: el hook detecta desconexión
   - Then: `isRecording` sigue `true` (el vídeo no se detiene), se emite un aviso al usuario

## Notas de implementación

- **MVP con overlay en reproducción (Opción C)**: el vídeo se graba limpio (sin overlay). En SessionDetail, el overlay con datos de golpes se dibuja encima del reproductor en tiempo real usando `impact.time - videoStartTime` para sincronizar. El usuario ve el overlay pero no está baked in en el MP4.
- **Export con overlay baked in → HT-013**: implementado como feature separada y dependiente. Usa `react-native-ffmpeg` para quemar el overlay en el vídeo tras la sesión. Ver spec HT-013.
- **Tamaño de archivo**: un vídeo de 15 min a 1080p puede pesar 1-2 GB. Valorar limitar a 720p o añadir aviso de espacio antes de grabar.
- **`expo-camera` vs `expo-video`**: `expo-camera` para grabación; `expo-video` para reproducción. Ambos forman parte del SDK de Expo y no requieren prebuild adicional si se usa Expo SDK 51+.
