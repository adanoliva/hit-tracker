## Descripción

Una vez finalizada la sesión, el usuario puede exportar el vídeo grabado (HT-012) con el overlay de datos de golpes quemado directamente en el MP4. El vídeo exportado puede compartirse sin necesidad de la app. Requiere que HT-012 esté implementado (vídeo limpio + timestamps de impactos).

## Criterios de aceptación

- [ ] En SessionDetail, botón "Exportar con overlay" visible si `training.videoPath` existe
- [ ] Al pulsar, se genera un MP4 nuevo con el overlay baked in (marcadores de golpe, intensidad, contador)
- [ ] Progreso de exportación visible (barra o spinner con % completado)
- [ ] El MP4 exportado se guarda en `<documentDirectory>/HitTracker/exports/<trainingId>_overlay.mp4`
- [ ] Botón "Compartir" disponible tras exportar (usa `expo-sharing`)
- [ ] Si el vídeo original no existe, el botón no aparece
- [ ] La exportación no bloquea la navegación (corre en background)

### Lógica de overlay

El overlay se construye con filtros `drawtext` de ffmpeg. Para cada impacto en `training.rounds[*].impacts`:

```
timestamp_en_video = impact.time - training.videoStartTime  (ms)
```

Por cada impacto se dibuja durante ~1s:
- Indicador visual (círculo o texto) con la intensidad del golpe
- Contador acumulado de golpes en esquina

Ejemplo de filtro ffmpeg (simplificado):
```
drawtext=text='GOLPE %{intensity}':enable='between(t,T_START,T_END)':x=50:y=50
```

El número de `drawtext` escala con el número de impactos — para sesiones largas (500+ golpes) puede ser lento. Alternativa: renderizar overlay como imagen PNG por frame con Canvas y usar `overlay` filter.

### `useVideoExport`

```ts
function useVideoExport(): {
  isExporting: boolean
  progress: number        // 0-100
  exportedPath: string | null
  exportWithOverlay(training: Training): Promise<string | null>
}
```

### Almacenamiento

```
<documentDirectory>/HitTracker/
└─ exports/
   └─ <trainingId>_overlay.mp4
```

Los exports no se borran automáticamente al eliminar la sesión (el usuario los habrá compartido). Avisar al usuario si quiere limpiarlos.

## Escenarios de test

1. **`useVideoExport` — sin videoPath**
   - Given: `training.videoPath === undefined`
   - When: se llama `exportWithOverlay(training)`
   - Then: devuelve `null` sin llamar a ffmpeg

2. **timestamps de overlay correctos**
   - Given: `videoStartTime = 1000000`, impact con `time = 1003000`
   - When: se calcula el timestamp en vídeo
   - Then: el drawtext aparece en el segundo 3 del vídeo

3. **progreso se actualiza**
   - Given: exportación en curso
   - When: ffmpeg reporta progreso
   - Then: `progress` sube de 0 a 100 de forma continua

## Notas de implementación

- **`ffmpeg-kit-react-native` vs `react-native-ffmpeg`**: `ffmpeg-kit` es el sucesor activo; `react-native-ffmpeg` está deprecado. Usar `ffmpeg-kit-react-native` con el paquete `min` para reducir tamaño del APK.
- **Rendimiento**: una sesión de 15 min con 300 golpes puede tardar 2-5 min en exportar en un móvil gama media. Mostrar progreso y permitir cancelar.
- **Calidad**: exportar a 720p para equilibrar calidad y tamaño. Configurable si se añade settings.
- **Sin preview en tiempo real**: el overlay no se muestra en tiempo real durante la sesión; solo se genera al exportar. El overlay en reproducción (HT-012, Opción C) es suficiente para revisar la sesión.
