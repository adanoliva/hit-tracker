## Descripción

Sincroniza automáticamente los archivos de sesiones de entrenamiento (training_XXX.json) con la carpeta `appDataFolder` de Google Drive. Al terminar una sesión se sube inmediatamente al Drive. Al conectar Google por primera vez (o en un dispositivo nuevo), se descargan todas las sesiones del Drive que no existen localmente.

## Criterios de aceptación

- [ ] Al terminar un entrenamiento y guardarse localmente, se sube automáticamente a Drive si hay cuenta conectada y hay red
- [ ] Si no hay red al terminar la sesión, la subida queda pendiente y se reintenta al recuperar conexión
- [ ] Al conectar una cuenta Google por primera vez, se descarga automáticamente todo el historial de Drive
- [ ] Al descargar, solo se añaden sesiones que no existen localmente (por `training.id`) — nunca se sobreescriben sesiones locales
- [ ] En la sección "Cuenta Google" de Perfiles se muestra el estado de sincronización: "Sincronizado", "Subiendo...", "Pendiente de sincronizar (N sesiones)"
- [ ] Si la subida falla (error de red o Drive), se reintenta hasta 3 veces con backoff exponencial; si agota reintentos, queda en cola pendiente
- [ ] La cola de subidas pendientes se persiste localmente para sobrevivir reinicios de la app
- [ ] El usuario puede pulsar "Sincronizar ahora" para forzar la subida de pendientes
- [ ] Eliminar una sesión localmente también la elimina en Drive (si existe)

### Lógica de negocio

#### Estructura de archivos en Drive (appDataFolder)
```
appDataFolder/
├── trainings/
│   ├── training_<id>.json
│   └── ...
└── profiles.json     ← gestionado por HT-004-c
```

#### Subida automática al terminar sesión
En `trainingStore.addTraining()`, después de persistir localmente:
```ts
async addTraining(training: Training) {
  // 1. Persistir local (comportamiento actual)
  await storage.saveTraining(training)  // mobile
  // await window.api.saveTraining(training)  // desktop

  // 2. Subir a Drive si cuenta conectada
  if (driveStore.account) {
    await driveStore.uploadTraining(training)
  }
}
```

#### `uploadTraining(training)` en driveStore
```ts
async uploadTraining(training: Training) {
  driveStore.setSyncStatus('syncing')
  try {
    await ensureValidToken()
    await driveApi.uploadFile({
      name: `training_${training.id}.json`,
      parents: ['appDataFolder'],
      mimeType: 'application/json',
      body: JSON.stringify(training)
    })
    // Eliminar de pendientes si estaba
    driveStore.removePending(training.id)
    driveStore.setSyncStatus('idle')
  } catch (e) {
    driveStore.addPending({ trainingId: training.id, retries: 0, lastAttempt: Date.now() })
    driveStore.setSyncStatus('pending')
  }
}
```

#### Cola de pendientes con reintentos
Backoff exponencial: espera `2^retries * 5000` ms entre reintentos (máx 3 reintentos = 5s, 10s, 20s).

```ts
async retryPending() {
  for (const pending of driveStore.pendingUploads) {
    const waitMs = Math.pow(2, pending.retries) * 5000
    if (Date.now() - pending.lastAttempt < waitMs) continue
    const training = trainingStore.trainings.find(t => t.id === pending.trainingId)
    if (training) await uploadTraining(training)
  }
}
```

La cola `pendingUploads` se persiste en:
- Mobile: `FileSystem.documentDirectory + 'HitTracker/drive-pending.json'`
- Desktop: `app.getPath('userData')/HitTracker/drive-pending.json`

`retryPending()` se llama al recuperar conexión de red (listener en `NetInfo` mobile / `net` module desktop).

#### Descarga inicial al conectar cuenta
```ts
async downloadAll() {
  driveStore.setSyncStatus('syncing')
  const files = await driveApi.listFiles({ q: "name contains 'training_'" })
  const localIds = new Set(trainingStore.trainings.map(t => t.id))
  
  for (const file of files) {
    const trainingId = file.name.replace('training_', '').replace('.json', '')
    if (!localIds.has(trainingId)) {
      const data = await driveApi.downloadFile(file.id)
      const training: Training = JSON.parse(data)
      await storage.saveTraining(training)  // solo local, sin re-subir a Drive
      trainingStore.addTrainingLocal(training)  // nuevo método que no re-sube
    }
  }
  driveStore.setSyncStatus('idle')
}
```

`downloadAll()` se llama inmediatamente después de que `HT-004-a` complete el OAuth con éxito.

#### Eliminación sincronizada
En `trainingStore.deleteTraining()`, después de eliminar localmente:
```ts
if (driveStore.account) {
  await driveStore.deleteFromDrive(trainingId)
}
```

`deleteFromDrive()` busca el archivo en Drive por nombre (`training_<id>.json`) y lo elimina. Si no existe en Drive, no falla.

## Escenarios de test

1. **Escenario**: Subida automática al terminar sesión
   - **Given**: Cuenta Google conectada, `driveApi.uploadFile` mockeado para resolver exitosamente
   - **When**: Se llama `trainingStore.addTraining(training)`
   - **Then**: `driveApi.uploadFile` es llamado con el training serializado, `driveStore.syncStatus === 'idle'`, `pendingUploads.length === 0`

2. **Escenario**: Fallo de red durante subida → queda en cola
   - **Given**: Cuenta conectada, `driveApi.uploadFile` lanza error de red
   - **When**: Se llama `trainingStore.addTraining(training)`
   - **Then**: `pendingUploads` contiene `{ trainingId: training.id, retries: 0 }`, `syncStatus === 'pending'`

3. **Escenario**: Descarga inicial no sobreescribe sesiones locales
   - **Given**: Local tiene training "abc"; Drive tiene "abc" y "xyz"
   - **When**: Se llama `downloadAll()`
   - **Then**: Solo se descarga y guarda "xyz". "abc" local no es modificado. `trainingStore.trainings` tiene ambos.

4. **Escenario**: Backoff respeta el tiempo de espera
   - **Given**: `pendingUploads = [{ trainingId: 't1', retries: 1, lastAttempt: Date.now() - 3000 }]`
   - **When**: Se llama `retryPending()` (espera mínima para retries=1 es 10000ms)
   - **Then**: No se intenta subir (aún no ha pasado el tiempo de espera)

5. **Escenario**: Eliminar sesión local también la elimina en Drive
   - **Given**: Cuenta conectada, training "abc" existe en Drive
   - **When**: `trainingStore.deleteTraining('abc')`
   - **Then**: `driveApi.deleteFile` es llamado con el file ID de `training_abc.json`

## Notas de implementación

- **`addTrainingLocal()`**: Añadir este método al store para que `downloadAll()` pueda persistir trainings descargados sin desencadenar una re-subida a Drive (evitar bucle).
- **Drive API calls**: Usar fetch directo contra la REST API de Google Drive v3 (no añadir el SDK de Google en el renderer). En Desktop, el main process hace las llamadas HTTP con Node.js `https` o `node-fetch`.
- **Concurrencia**: Si el usuario termina múltiples sesiones seguidas sin conexión, la cola puede tener varias entradas. `retryPending()` las procesa secuencialmente para no saturar la API.
- **Rate limits Drive API**: Google Drive permite 1000 req/100s por usuario. Para un uso normal (1-3 sesiones/día) no es un problema.
