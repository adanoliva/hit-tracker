## Descripción

Cuando el usuario tiene un sensor BLE conectado, aparece un botón "Calibrar" en la tarjeta del perfil activo. Al pulsarlo se lanza un asistente guiado de 3 series (ligero → normal → fuerte) de 5 golpes cada una. Al completar las 3 series el sistema calcula automáticamente `threshold` y `sensitivity` óptimos para ese usuario y los guarda directamente en el perfil activo.

Resuelve el problema actual de calibración manual: el usuario no sabe qué valores poner en los sliders sin probar a ciegas.

## Criterios de aceptación

- [ ] El botón "Calibrar" solo es visible en la tarjeta del perfil activo **y** cuando `deviceStore.connected !== null`
- [ ] El asistente muestra 3 pasos secuenciales: Ligero, Normal, Fuerte
- [ ] Cada paso muestra un contador de golpes registrados (ej. `3 / 5`) y avanza automáticamente al siguiente al llegar a 5
- [ ] Solo se registra un golpe si la magnitud supera `MIN_CALIB_HIT = 200` raw (filtra ruido y reposo ~128)
- [ ] Al completar el paso 3, se calculan y guardan inmediatamente `threshold` y `sensitivity` en el perfil activo
- [ ] Se muestra una pantalla de resultado con los nuevos valores y un botón "Listo" para cerrar
- [ ] Si el sensor se desconecta durante el asistente, se cancela y muestra mensaje de error
- [ ] Si `heavyAvg ≤ lightAvg * 1.2` (rango insuficiente), se muestra error "Los golpes fuertes no fueron suficientemente distintos a los suaves. Inténtalo de nuevo" y se permite reiniciar
- [ ] En cada paso hay un botón "Repetir serie" que descarta los golpes actuales del paso y reinicia el contador a 0
- [ ] El asistente es cancelable en cualquier momento (botón X / back) sin guardar cambios

interface CalibWizardState {

### Lógica de negocio

#### Detección de golpe durante calibración

Se reutiliza la misma lógica de pico que `useSensorData`:
- Se guarda la lectura anterior (`prevReading`)
- Un golpe se registra cuando: `!isRising && prev.magnitude > MIN_CALIB_HIT && now - lastHitTime > 200ms`
- El valor recogido es `prev.magnitude` (en el pico)
- `MIN_CALIB_HIT = 200` (constante local, filtra reposo ~128 y roces)

#### Actualización de `analyzeCalibrationSamples`

La función existente usa la fórmula antigua. Debe actualizarse a la nueva fórmula de `calculateIntensity`:

```
intensity = (magnitude - threshold*10) / (sensitivity*10) * 100
```

Nueva lógica:
```ts
analyzeCalibrationSamples(light, normal, heavy) {
  const lightAvg = avg(light)
  const heavyAvg = avg(heavy)

  // base de detección = 80% del promedio de golpes ligeros
  const base = lightAvg * 0.8

  // rango: de base hasta heavyAvg = 100% de intensidad
  const range = heavyAvg - base

  // threshold almacenado = base / 10  (ya que detection usa threshold * 10)
  // sensitivity almacenado = range / 10  (ya que formula usa sensitivity * 10)
  const suggestedThreshold = Math.round((base / 10) * 10) / 10
  const suggestedSensitivity = Math.round((range / 10) * 10) / 10

  return { suggestedThreshold, suggestedSensitivity }
}
```

Validación previa al calcular: si `range < base * 0.2` → lanzar error "rango insuficiente" (heavy no supera significativamente a light).

#### Flujo del asistente (máquina de estados)

```
idle
  → [pulsar "Calibrar"] → step: 'light', light: []
      → [golpe detectado, light.length < 5] → light.push(magnitude)
      → [light.length === 5] → step: 'normal', normal: []
          → [golpe detectado, normal.length < 5] → normal.push(magnitude)
          → [normal.length === 5] → step: 'heavy', heavy: []
              → [golpe detectado, heavy.length < 5] → heavy.push(magnitude)
              → [heavy.length === 5] → calcular + validar
                  → [rango OK] → updateProfile(id, {threshold, sensitivity}) → step: 'done'
                  → [rango insuficiente] → step: 'error', errorMsg: "..."
      → [pulsar "Repetir serie"] → limpiar array del paso actual, contador a 0
      → [pulsar X / cancelar] → cerrar sin guardar
  → [sensor desconectado en cualquier step activo] → cancelar, mostrar error
```

#### Escucha del sensor por plataforma

**Desktop** — `listen('ble-sensor-data', handler)` de `@tauri-apps/api/event`. Registrar en `useEffect` con cleanup al desmontar el modal.

**Mobile** — `useBleReading({ deviceId, active: true, onReading: handler })`. `deviceId` = `deviceStore.connected?.mac`.

Ninguna. Usa infraestructura BLE ya existente.

## Escenarios de test

Los tests cubren la lógica de `analyzeCalibrationSamples` actualizada. El wizard es UI/estado y se verifica manualmente.

1. **Escenario**: calibración normal con valores bien diferenciados
   - **Given**: light = [250, 260, 240, 255, 245], heavy = [900, 950, 920, 880, 910]
   - **When**: `analyzeCalibrationSamples(light, [], heavy)` (normal no afecta al cálculo)
   - **Then**: `suggestedThreshold ≈ 20` (base=250*0.8=200, /10=20), `suggestedSensitivity ≈ 70` (range=900-200=700, /10=70)

2. **Escenario**: rango insuficiente (heavy ≈ light)
   - **Given**: light = [300, 310, 290, 305, 295], heavy = [320, 330, 310, 325, 315]
   - **When**: `analyzeCalibrationSamples(light, [], heavy)`
   - **Then**: la función lanza error o devuelve `{ error: 'rango insuficiente' }` — a decidir en implementación. Recomendado: devolver `null` y que el caller gestione el error

3. **Escenario**: valores extremos — usuario muy potente
   - **Given**: light = [400, 420, 380, 410, 390], heavy = [2500, 2600, 2400, 2550, 2450]
   - **When**: `analyzeCalibrationSamples(light, [], heavy)`
   - **Then**: `suggestedThreshold` y `suggestedSensitivity` dentro de los rangos válidos del slider (1-100), no overflow

4. **Escenario**: desconexión durante calibración
   - **Given**: wizard en step 'normal', 3 golpes registrados
   - **When**: `deviceStore.connected` pasa a `null`
   - **Then**: modal se cierra (o muestra error), perfil no modificado

## Notas de implementación

- El asistente se implementa como un modal/overlay **inline** dentro de `Profiles/index.tsx` en ambas plataformas (no un archivo separado), siguiendo el patrón existente del modal "Acerca de".
- En desktop el sensor llega por Tauri events; en mobile por `useBleReading`. La lógica de detección de picos es idéntica — usar un `useRef` para `prevReading` y `lastHitTime`, mismo cooldown de 200ms.
- El array `normal[]` se recoge pero **no influye en el cálculo** de threshold/sensitivity (solo light y heavy). Se guarda igualmente en `CalibrationData` si se decide persistirlo en el futuro.
- Si el usuario ya tiene valores calibrados, el asistente los sobreescribe sin aviso (aplicación directa acordada). El historial de calibración anterior se pierde.
- En mobile, `useBleReading` solo debe activarse cuando el wizard está abierto (`active: wizardOpen`), no siempre.
- Clampar los valores calculados al rango del slider (threshold: 0-100, sensitivity: 1-100) antes de guardar, por si los cálculos dan fuera de rango.
