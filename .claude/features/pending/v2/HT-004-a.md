## Descripción

Permite al usuario conectar y desconectar su cuenta de Google desde la pantalla de Perfiles. Gestiona el flujo OAuth2, almacena los tokens de forma segura y expone el estado de conexión al resto de la app. Es la base sobre la que HT-004-b y HT-004-c construyen la sincronización.

## Criterios de aceptación

- [ ] En la pantalla de Perfiles existe una sección "Cuenta Google" con el estado actual (conectado/desconectado)
- [ ] Si desconectado: botón "Conectar con Google" que lanza el flujo OAuth2
- [ ] Si conectado: muestra el email de la cuenta y botón "Desconectar"
- [ ] Tras OAuth exitoso, los tokens se almacenan de forma segura (no en texto plano)
- [ ] Al desconectar, los tokens se eliminan completamente del almacenamiento local
- [ ] Al relanzar la app con cuenta ya conectada, el estado se restaura sin pedir login de nuevo
- [ ] Si el access token ha expirado, se refresca automáticamente con el refresh token sin intervención del usuario
- [ ] Si el refresh falla (refresh token revocado), se muestra estado "Desconectado" y se limpian los tokens
- [ ] El estado de conexión es accesible globalmente desde un store para que HT-004-b y HT-004-c puedan consultarlo
- [ ] Desconectar NO elimina los datos locales ni los archivos de Drive

### Lógica de negocio

#### Scopes OAuth2 requeridos
```
https://www.googleapis.com/auth/drive.appdata
```
Usar `drive.appdata` (carpeta oculta de la app en Drive, no visible en el Drive del usuario). Esto es más limpio y no requiere permiso de acceso a todos los archivos.

#### Flujo OAuth Mobile (expo-auth-session)
```ts
const discovery = await fetchDiscoveryAsync('https://accounts.google.com')
const request = new AuthRequest({
  clientId: GOOGLE_CLIENT_ID_ANDROID,
  scopes: ['openid', 'email', 'profile', 'https://www.googleapis.com/auth/drive.appdata'],
  redirectUri: makeRedirectUri({ scheme: 'hittracker' })
})
const result = await request.promptAsync(discovery)
// result.type === 'success' → intercambiar code por tokens
```

#### Flujo OAuth Desktop (Electron)
1. Main process abre URL de autorización en el navegador del sistema con `shell.openExternal(authUrl)`
2. Registrar protocolo custom `hittracker://` con `app.setAsDefaultProtocolClient('hittracker')`
3. Al recibir el callback en `hittracker://oauth?code=XXX`, intercambiar code por tokens en el main process
4. Enviar tokens al renderer via `webContents.send('google-auth-success', tokens)`

#### Almacenamiento de tokens
- **Mobile**: `expo-secure-store` → clave `ht_google_tokens` → valor JSON serializado de `GoogleAccount`
- **Desktop**: `app.getPath('userData')/HitTracker/.tokens` encriptado con `safeStorage.encryptString()` (API nativa Electron, usa llavero del OS)

#### Refresco automático de tokens
Antes de cualquier llamada a Drive API, verificar `account.expiresAt`:
```ts
if (Date.now() > account.expiresAt - 60000) {
  // refrescar con refresh_token
  const refreshed = await refreshAccessToken(account.refreshToken)
  if (refreshed.error) {
    driveStore.setAccount(null)  // limpiar estado
    return
  }
  driveStore.setAccount({ ...account, accessToken: refreshed.access_token, expiresAt: Date.now() + refreshed.expires_in * 1000 })
}
```

#### Credenciales OAuth (Google Cloud)
- Crear proyecto en Google Cloud Console con OAuth2 credentials
- Android client ID + scheme `hittracker` para mobile
- Desktop: "Desktop app" client ID para Electron
- Las credenciales se inyectan como variables de entorno en build time (`VITE_GOOGLE_CLIENT_ID` para desktop, `EXPO_PUBLIC_GOOGLE_CLIENT_ID` para mobile)

## Escenarios de test

1. **Escenario**: Estado inicial sin cuenta conectada
   - **Given**: App recién instalada, sin tokens almacenados
   - **When**: Se inicializa `driveStore`
   - **Then**: `driveStore.account === null`, sección "Cuenta Google" muestra "Conectar con Google"

2. **Escenario**: Restauración de sesión al relanzar app
   - **Given**: Tokens válidos almacenados en secure storage, `expiresAt` en el futuro
   - **When**: App arranca y lee tokens
   - **Then**: `driveStore.account` se popula con los datos del token y se muestra el email

3. **Escenario**: Token expirado se refresca automáticamente
   - **Given**: `account.expiresAt < Date.now()` y refresh token válido
   - **When**: Se llama a `ensureValidToken()`
   - **Then**: Se obtiene nuevo access token, `driveStore.account.expiresAt` se actualiza, sin intervención del usuario

4. **Escenario**: Refresh token revocado
   - **Given**: El usuario revocó el acceso desde cuentas.google.com
   - **When**: Se llama a `ensureValidToken()` y el refresh falla con error 401
   - **Then**: `driveStore.setAccount(null)`, tokens eliminados del secure storage, UI muestra "Desconectado"

5. **Escenario**: Desconexión
   - **Given**: Usuario conectado con email "user@gmail.com"
   - **When**: Pulsa "Desconectar" y confirma
   - **Then**: Tokens eliminados, `driveStore.account === null`, datos locales intactos

## Notas de implementación

- **Google Cloud setup**: documentar en `docs/GOOGLE-DRIVE-SETUP.md` los pasos para crear las credenciales (fuera del scope del agente dev, pero necesario para que funcione).
- **Scope `drive.appdata`**: los archivos en `appDataFolder` no son visibles en drive.google.com por el usuario, solo accesibles por la app. Es la opción más limpia para un backup silencioso.
- **Desktop protocol handler**: en desarrollo (electron-vite dev), el protocolo custom no funciona igual que en producción. Usar un fallback con ventana de login manual si es necesario en dev.
- **No usar Firebase Auth**: añadiría una dependencia pesada innecesaria. OAuth2 directo contra Google es suficiente.
