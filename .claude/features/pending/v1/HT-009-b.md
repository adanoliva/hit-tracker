## Descripción

Con el firmware V2 (HT-009-a) la magnitud de cada golpe es un entero grande (~128 reposo, 600-1500+ golpe fuerte). Esta feature cambia lo que ve el usuario durante la sesión:

1. **Valor raw durante sesión**: el "Power máx" que se muestra en tiempo real pasa de mostrar `intensity` (0-100) a mostrar `magnitude` (entero raw, ej. 847).
2. **Gráfica en porcentaje relativo**: el eje Y de la gráfica de golpes muestra el porcentaje respecto al `userPowerMax` calculado con HT-008 (media de las últimas 5 sesiones). Si un golpe supera el 100% del user power, el eje Y se extiende (ej. muestra 105, 110...).
3. **Referencia fija al inicio**: el `userPowerMax` se carga al arrancar la sesión y no cambia durante ella, para no alterar el estado `isValid` de golpes ya registrados.

## Criterios de aceptación

- [ ] El stat "Power máx" en `TrainingRound` (desktop y mobile) muestra `Math.max(...impacts.map(i => i.magnitude))` en lugar de `powerMax` (intensity)
- [ ] El eje Y de la gráfica muestra porcentaje: `(impact.magnitude / userPowerRef) * 100`, redondeado a entero
- [ ] Si `userPowerRef = 0` (sin sesiones previas), la gráfica usa `intensity` como fallback (escala 0-100)
- [ ] El eje Y se ajusta dinámicamente: dominio `[0, Math.max(105, maxChartValue + 5)]` para que siempre haya margen y se vean golpes que superan el 100%
- [ ] El `userPowerRef` se obtiene de `getUserPowerMax(profile.id)` al inicio de la sesión y no se recalcula durante ella
- [ ] La línea de referencia del umbral válido (actualmente `powerMax * 0.8`) se mantiene pero expresada en la misma escala % del eje Y
- [ ] `Impact.magnitude` se persiste en el JSON de la sesión (ya existe el campo — verificar que se guarda correctamente con valores grandes)
- [ ] El stat "Power máx" muestra el número raw sin decimales (entero)

### Lógica de negocio

#### userPowerRef — referencia fija de sesión

En el componente padre de Training (`index.tsx`), al montar:

```ts
const getUserPowerMax = useTrainingStore((s) => s.getUserPowerMax)
// Capturado una sola vez al montar el componente, no reactivo
const userPowerRef = useRef(getUserPowerMax(profile.id))
```

Se pasa a `TrainingRound` como prop `userPowerRef: number`.

#### Stat "Power máx"

```ts
// Antes: powerMax (intensity, 0-100)
// Ahora: magnitud máxima de los impacts de la ronda actual
const rawPowerMax = impacts.length > 0
  ? Math.max(...impacts.map(i => i.magnitude))
  : 0
```

Mostrar `rawPowerMax` como entero (sin unidades en la UI — el número habla solo).

#### Datos de la gráfica

```ts
const chartData = impacts.map((i) => ({
  time: i.time,
  // Si hay referencia, expresar en % del user power max
  // Si no hay referencia, usar intensity directamente (0-100)
  value: userPowerRef > 0
    ? Math.round((i.magnitude / userPowerRef) * 100)
    : i.intensity,
  isValid: i.isValid
}))

// Dominio Y dinámico
const maxChartValue = chartData.length > 0
  ? Math.max(...chartData.map(d => d.value))
  : 100
const yDomain: [number, number] = [0, Math.max(105, maxChartValue + 5)]
```

#### Línea de referencia del umbral válido

La línea de referencia que marca el umbral de golpe válido (actualmente `powerMax * 0.8`) pasa a expresarse en la misma escala:

```ts
// Con referencia: la línea está en profile.validHitThreshold (ya es %, 0-100)
// Sin referencia: igual que antes
const refLine = profile.validHitThreshold ?? 80
// La línea siempre está en el mismo valor numérico que el umbral configurado
// porque tanto el eje Y como el umbral están en % del user power max
```

#### Props de TrainingRound

```ts
interface TrainingRoundProps {
  // ... existentes ...
  userPowerRef: number  // nuevo — 0 si no hay sesiones previas
}
```

### Tipos nuevos o modificados

Solo se añade `userPowerRef: number` a las props de `TrainingRound` (no es un tipo del dominio).

### Dependencias entre features

- **HT-008** — `getUserPowerMax()` en el store
- **HT-009-a** — `Impact.magnitude` con valores raw grandes (sin esto, los números serían 50-100 m/s², no 600-1500)

## Escenarios de test

1. **Gráfica en % con referencia**
   - **Given**: `userPowerRef = 800`, impacto con `magnitude = 840`
   - **When**: se calcula el valor del chart
   - **Then**: `Math.round((840 / 800) * 100) = 105` — se muestra por encima del 100%

2. **Fallback sin sesiones previas**
   - **Given**: `userPowerRef = 0` (primera sesión del usuario)
   - **When**: se calculan los datos del chart
   - **Then**: se usa `i.intensity` (0-100) — la gráfica funciona igual que antes

3. **Dominio Y se extiende cuando se supera el 100%**
   - **Given**: chartData con valores [80, 95, 110]
   - **When**: se calcula yDomain
   - **Then**: `yDomain = [0, 115]` (maxChartValue 110 + 5)

4. **userPowerRef no cambia durante la sesión**
   - **Given**: sesión iniciada con `userPowerRef = 700`; usuario da golpe de magnitud 1200
   - **When**: el golpe se registra y se añade a `impacts`
   - **Then**: `userPowerRef` sigue siendo 700 (ref capturada al inicio con `useRef`)

5. **Stat Power máx muestra magnitud raw**
   - **Given**: impacts con magnitudes [320, 640, 980]
   - **When**: se renderiza el stat
   - **Then**: muestra `980` (entero, sin decimales)

## Notas de implementación

- El campo `powerMax` de `Training` y `RoundStats` sigue almacenando el máximo de `intensity` (0-100) — es la referencia interna para `isValid`. No cambia.
- `Impact.magnitude` ya existe en el tipo y se persiste. Con V2 del firmware tendrá valores grandes; con V1 tendrá valores pequeños (m/s²). La gráfica funciona igual en ambos casos si `userPowerRef` está en la misma escala.
- En mobile, el equivalente de `TrainingRound.tsx` está en `mobile/src/components/Training/TrainingRound.tsx`.
