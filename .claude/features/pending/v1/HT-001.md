## Descripción

Eliminar los dos modos temporales que permitían usar hardware simulado durante el desarrollo:

1. **Desktop — Sensor mock**: un servidor WebSocket local (`localhost:7331`) simulaba el ESP32. La app lo detectaba via `/health` y lo trataba como dispositivo "Simulador (local)".
2. **Mobile — Teléfono como sensor**: el propio móvil actuaba como sensor BLE usando `react-native-sensors`, identificado por `PHONE_SENSOR_ID = 'PHONE_SENSOR'`.

Ambos modos eran explícitamente temporales (indicado en `CLAUDE.md`) hasta que el hardware ESP32 real estuviera disponible. Esta feature los elimina limpiamente, simplificando el código de conexión y la UI de dispositivos.

El servidor mock de desktop (`tools/mock-sensor.mjs`) también se elimina junto con el script `npm run mock` del `package.json`.

### Lógica de negocio

No hay lógica nueva. La eliminación es puramente de ramas de código condicionales.

**Desktop — flujo de escaneo post-eliminación:**
El escaneo BLE ya no incluye `detectMockSensor()`. Solo se listan dispositivos BLE reales. La función `handleConnect` solo tiene el path BLE real.

**Mobile — flujo de conexión post-eliminación:**
La pantalla Devices solo muestra dispositivos BLE escaneados. No hay botón "Usar este móvil". `usePhoneSensor` deja de existir. `Training` y `Game` solo reciben datos del sensor BLE (vía el hook existente de BLE que no se modifica).

**Precaución — `placement` en Device persistido:**
Los `devices.json` existentes en desktop y los archivos de dispositivos en mobile pueden tener objetos con `placement` guardado. No hace falta migración: el campo simplemente será ignorado al deserializar (TypeScript no valida en runtime). Si el tipo `Device` ya no lo declara, el compilador ignorará el campo extra en el JSON leído.

## Escenarios de test

1. **Escenario**: Dispositivos guardados con `placement` no rompen la carga
   - **Given**: existe un `devices.json` con un device que tiene `placement: 'front-vertical'`
   - **When**: la app carga y deserializa los dispositivos guardados
   - **Then**: el device se carga correctamente, el campo `placement` se ignora en runtime sin error de TypeScript ni crash

2. **Escenario**: UI de Devices desktop no muestra simulador tras eliminación
   - **Given**: la app desktop está en la pantalla Devices sin ningún ESP32 cercano
   - **When**: el usuario pulsa "Buscar dispositivos"
   - **Then**: la lista queda vacía (o con dispositivos BLE reales si los hay); no aparece "Simulador (local)"

3. **Escenario**: UI de Devices mobile no muestra opción de teléfono
   - **Given**: la app mobile está en la pantalla Devices
   - **When**: el usuario ve la pantalla completa
   - **Then**: no existe botón "Usar este móvil como sensor" ni modal `PhoneSensorPicker`

4. **Escenario**: TypeScript compila sin referencias rotas
   - **Given**: se han eliminado los archivos y referencias
   - **When**: se ejecuta `tsc --noEmit` en desktop y mobile
   - **Then**: cero errores de compilación

## Notas de implementación

- El hook `usePhoneSensor` usa `react-native-sensors` (paquete). No eliminar el paquete del `package.json` en esta feature — puede existir como dependencia sin uso activo. Si se quiere eliminar también el paquete, hacerlo en una feature separada o añadirlo al scope explícitamente antes de implementar.
- En `mobile/src/components/Devices/index.tsx` hay emojis 📱 en el nombre del phoneDevice. Tras la eliminación, asegurarse de que el renderizado de la lista de dispositivos BLE reales no queda con código muerto ni ramas vacías.
- No hay assets que eliminar: `sensor-placement.png` lo usa `PhoneSensorPicker.tsx`. Al eliminar ese archivo, la imagen queda huérfana en `mobile/assets/`. Puede dejarse o eliminarse; no afecta al build.
