## Descripción

Reemplaza el sistema actual de dos tabs separados (Dispositivos para conectar, Perfiles para seleccionar) por una pantalla combinada "Sesión activa" que registra el par activo Perfil-Sensor. Al conectar un dispositivo, se presenta inmediatamente la selección de perfil. Este par queda registrado en el store para preparar el terreno al futuro sistema multi-sensor multi-usuario. La pantalla también muestra si existe calibración específica para el par activo o solo se está usando el fallback.

## Criterios de aceptación

- [ ] Existe una pantalla/modal "Sesión activa" accesible desde el Dashboard o como tab
- [ ] La pantalla tiene dos pasos: (1) seleccionar/conectar sensor, (2) seleccionar perfil
- [ ] Al completar ambos pasos, se registra el par `{ deviceMac, profileId }` como sesión activa en el store
- [ ] El par activo persiste entre reinicios de la app (guardado en disco)
- [ ] La pantalla muestra claramente si el par tiene calibración específica o está usando fallback genérico
- [ ] Si hay calibración específica: badge "✓ Calibrado para este sensor"
- [ ] Si solo hay fallback: badge "⚠ Usando calibración genérica" + enlace "Calibrar ahora →" (apunta a HT-006-c)
- [ ] Desde cualquier lugar de la app, el par activo `{ device, profile }` es accesible via store
- [ ] El tab de Dispositivos y el tab de Perfiles mantienen su funcionalidad actual (CRUD), pero ya no son el punto de entrada para "activar"
- [ ] Durante un entrenamiento activo, no se puede cambiar el par activo (botón deshabilitado)
- [ ] Si no hay ningún dispositivo guardado: se muestra el estado vacío con botón "Añadir sensor" que navega a Dispositivos
- [ ] En mobile: el flujo de "teléfono como sensor" también pasa por esta pantalla (PHONE_SENSOR_ID)

#### Registro del par activo
Al pulsar "CONFIRMAR SESIÓN":
```ts
sessionStore.setActiveSession({
  deviceMac: selectedDevice.mac,
  profileId: selectedProfile.id,
  pairedAt: Date.now()
})
// Conectar el dispositivo BLE si no está ya conectado
deviceStore.setConnected(selectedDevice.mac)
// Persistir
storage.saveActiveSession(activeSession)
```

#### `isCalibrated()` en sessionStore
```ts
isCalibrated(): boolean {
  const profile = this.getActiveProfile()
  const session = this.activeSession
  if (!profile || !session) return false
  return profile.deviceCalibrations.some(c => c.deviceMac === session.deviceMac)
}
```

#### Integración con Training
`TrainingSetup.tsx` pasa de leer `deviceStore.connected` + `profileStore.getSelected()` a leer `sessionStore.getActiveDevice()` + `sessionStore.getActiveProfile()`.

El botón "Comenzar entrenamiento" está habilitado solo si `sessionStore.activeSession !== null`.

#### Persistencia del par activo
- **Desktop**: `app.getPath('userData')/HitTracker/active-session.json`
- **Mobile**: `{documentDirectory}/HitTracker/active-session.json`

Al arrancar la app, cargar `active-session.json`. Si el dispositivo del par ya no existe en `deviceStore.devices`, limpiar `activeSession`.

#### Selector de sensor (step 1)
Lista los dispositivos de `deviceStore.devices`. Permite también navegar a la pantalla de Dispositivos para añadir uno nuevo. En mobile, incluye "📱 Este móvil" (PHONE_SENSOR_ID).

#### Selector de perfil (step 2)
Lista los perfiles de `profileStore.profiles`. No permite crear perfiles desde aquí (ir a Perfiles para eso).

## Escenarios de test

1. **Escenario**: `isCalibrated()` devuelve `true` cuando existe calibración para el par
   - **Given**: `activeSession = { deviceMac: 'AA:BB', profileId: 'p1' }`; perfil 'p1' tiene `deviceCalibrations: [{ deviceMac: 'AA:BB', ... }]`
   - **When**: `sessionStore.isCalibrated()`
   - **Then**: `true`

2. **Escenario**: `isCalibrated()` devuelve `false` con fallback genérico
   - **Given**: Mismo par pero el perfil tiene `deviceCalibrations: []`
   - **When**: `sessionStore.isCalibrated()`
   - **Then**: `false`

3. **Escenario**: Sesión activa con dispositivo eliminado se limpia al arrancar
   - **Given**: `active-session.json` tiene `deviceMac: 'OLD:MAC'`; `deviceStore.devices` no contiene ese MAC
   - **When**: App arranca y carga `active-session`
   - **Then**: `sessionStore.activeSession === null`

4. **Escenario**: Cambiar perfil activo desde la pantalla registra el nuevo par
   - **Given**: Par activo `{ deviceMac: 'AA:BB', profileId: 'p1' }`
   - **When**: Usuario selecciona perfil 'p2' y confirma
   - **Then**: `sessionStore.activeSession.profileId === 'p2'`, `pairedAt` actualizado

5. **Escenario**: Botón confirmar deshabilitado durante entrenamiento activo
   - **Given**: `trainingStore.activePhase !== 'idle'`
   - **When**: Se renderiza la pantalla Sesión activa
   - **Then**: El botón "CONFIRMAR SESIÓN" está deshabilitado

## Notas de implementación

- **Backward compatibility**: `deviceStore.connected` y `profileStore.selectedProfileId` siguen existiendo y se sincronizan con `sessionStore.activeSession` al confirmar. Esto minimiza cambios en el resto de la app.
- **Tab vs modal**: En desktop, la pantalla "Sesión activa" puede ser un nuevo tab en la navbar (reemplazar el tab de Dispositivos o añadir uno nuevo). En mobile, puede ser un tab dedicado. Decisión visual del dev: lo importante es que sea accesible sin estar en Training.
- **Icono sugerido**: `Users` o `Link` de Lucide para el tab de Sesión Activa.
- **No eliminar tab Dispositivos ni Perfiles**: siguen siendo accesibles para gestión CRUD. Solo cambia el flujo de "activar".
