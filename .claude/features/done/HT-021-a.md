## Descripción

Pantalla accesible desde el tab Entrenamiento que muestra el catálogo completo de ejercicios organizados por categoría. El usuario puede ver los detalles de cada ejercicio, añadir ejercicios personalizados y eliminar los que no son del catálogo base (los del JSON local no se pueden borrar). Es el punto de entrada para la búsqueda/importación de wger (HT-021-b).

## Criterios de aceptación

- [x] Tres pestañas o secciones: **Calentamiento**, **Core/Fullbody**, **Boxing**
- [x] Cada ejercicio muestra: nombre, músculos principales, duración/reps, dificultad
- [x] Al tocar un ejercicio, se abre panel de detalle con descripción completa
- [x] Los ejercicios del catálogo base (JSON) tienen un indicador "Base" y no se pueden eliminar
- [x] Los ejercicios importados de wger o creados por el usuario pueden eliminarse (swipe-delete)
- [x] Botón "Buscar en wger" en las secciones Calentamiento y Core/Fullbody (abre HT-021-b)
- [x] Botón "Añadir ejercicio de boxeo" en la sección Boxing (abre formulario de creación manual)
- [x] Los ejercicios custom de boxing se guardan en local storage (formato `Exercise` estándar)
- [x] Buscador local (texto) que filtra por nombre en la categoría activa

## Requisitos técnicos

### Archivos a crear

- `src/components/Entrenamiento/CatalogScreen.tsx` — pantalla principal del catálogo
- `src/components/Entrenamiento/ExerciseDetailSheet.tsx` — bottom sheet / modal de detalle
- `src/components/Entrenamiento/BoxingExerciseForm.tsx` — formulario para crear ejercicio de boxing

### Persistencia de ejercicios custom

Los ejercicios no-base se guardan en `<documentDirectory>/HitTracker/custom_exercises.json`.

Se necesita extender `exerciseService` (o crear un `customExerciseStore`) para:
- `getCustomExercises(): Exercise[]`
- `addCustomExercise(ex: Omit<Exercise, 'id'>): void` — id = slug generado
- `deleteCustomExercise(id: string): void`

`getAll()` y `getByCategory()` deben incluir tanto base como custom.

### Ejercicio custom de boxing

Un ejercicio de boxing en el catálogo es diferente a una sesión; representa una **combinación o drill** usado como unidad del catálogo:

```ts
// Ejemplo de ejercicio de boxing en el catálogo:
{
  id: "combo-1-2-jab-cross",
  name: "Combinación 1-2 (Jab-Cross)",
  category: "boxing",  // nueva categoría a añadir a ExerciseCategory
  muscles: ["Hombros", "Pecho", "Core"],
  equipment: "none",
  description: "Secuencia base del boxeo. Jab de exploración seguido de cross potente. Trabaja la distancia y la rotación de caderas.",
  duration: 60,  // segundos de práctica del drill
  rest: 30,
  difficulty: "easy"
}
```

Esto implica añadir `'boxing'` a `ExerciseCategory` en `shared/types/index.ts`.

### BoxingExerciseForm

Campos:
- Nombre (obligatorio)
- Descripción / instrucciones
- Duración en segundos (o reps)
- Descanso en segundos
- Dificultad (easy/medium/hard)
- Músculos (chips seleccionables de una lista predefinida)

## Notas de implementación

- El catálogo Boxing base lo creamos nosotros (no viene de wger). Inicialmente puede ser el propio JSON con ~10 combinaciones fundamentales de boxeo.
- `ExerciseCategory` necesita la nueva opción `'boxing'` — actualizar el tipo y el JSON de ejercicios.
- Los ejercicios base del JSON no tienen campo `isBase`; se detectan por si su ID existe en `exercises.json`. Los custom tienen IDs generados con prefijo `custom-`.
