## Descripción

Define el modelo de datos `WorkoutPlan` (plantilla de entrenamiento reutilizable), el store Zustand y la persistencia en disco. Es la base de datos de HT-019 y HT-020. Un `WorkoutPlan` agrupa tres fases: calentamiento (lista de ejercicios del catálogo), core/fullbody (lista de ejercicios del catálogo) y boxing (configuración de rounds con combos opcionales).

## Criterios de aceptación

- [x] Tipos `WorkoutPlan`, `BoxingRoundScript`, `BoxingPhaseConfig` definidos en `shared/types/index.ts`
- [x] `workoutPlanStore` con `plans[]`, `addPlan`, `updatePlan`, `deletePlan`, `getById`
- [x] Los planes se persisten en `<documentDirectory>/HitTracker/workout_plans.json`
- [x] Al arrancar la app, los planes se cargan desde disco (igual que `profileStore`)
- [x] `addPlan` genera un `id` único (timestamp) y `createdAt`
- [x] Los planes sobreviven a reinicios de la app

## Requisitos técnicos

### Tipos nuevos (`shared/types/index.ts`)

```ts
export interface BoxingRoundScript {
  round: number         // 1-based
  combo: string         // "1-2-3-Slip Iz-3b-6" — notación libre
  note?: string         // nota opcional para el entrenador
}

export interface BoxingPhaseConfig {
  roundDuration: number   // segundos (0 = modo libre)
  numRounds: number
  restDuration: number    // segundos
  roundScripts: BoxingRoundScript[]  // uno por round, puede tener menos que numRounds
}

export interface WorkoutPlan {
  id: string
  name: string
  createdAt: number
  warmupExerciseIds: string[]    // IDs del catálogo ejercicios (Exercise.id)
  coreExerciseIds: string[]      // IDs del catálogo ejercicios
  boxing: BoxingPhaseConfig
}
```

### Store (`src/core/stores/workoutPlanStore.ts`)

```ts
interface WorkoutPlanStore {
  plans: WorkoutPlan[]
  loaded: boolean
  load: () => Promise<void>
  addPlan: (plan: Omit<WorkoutPlan, 'id' | 'createdAt'>) => void
  updatePlan: (id: string, changes: Partial<Omit<WorkoutPlan, 'id' | 'createdAt'>>) => void
  deletePlan: (id: string) => void
  getById: (id: string) => WorkoutPlan | undefined
}
```

### Persistencia

- Archivo: `<FileSystem.documentDirectory>HitTracker/workout_plans.json`
- Patrón idéntico al de `profileStore` o `trainingStore` existentes.
- `load()` se llama en el arranque de la app (mismo lugar donde se llaman los otros stores).

### Re-exports

- `src/core/stores/workoutPlanStore.ts` re-exporta del store

## Escenarios de test

1. **addPlan** genera id y createdAt automáticamente; el plan aparece en `plans[]`
2. **deletePlan** elimina el plan de `plans[]`
3. **getById** devuelve el plan correcto o `undefined` si no existe

## Notas de implementación

- `roundScripts` es una lista sparse: si un round no tiene script, simplemente no aparece. El componente de sesión busca `roundScripts.find(s => s.round === currentRound)`.
- La validación de que `warmupExerciseIds` existan en el catálogo se hace en la UI del builder (HT-019), no en el store.
- Un `WorkoutPlan` sin calentamiento o sin core es válido (`warmupExerciseIds: []`).
