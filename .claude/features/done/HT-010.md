## Descripción

Actualmente los trainings guardados en disco no llevan versión de la app que los creó. Cuando cambia el formato de los datos (como ocurre en HT-009-a con `Impact.magnitude` pasando de m/s² a raw/16), no hay forma de saber qué sesiones son del formato antiguo ni de convertirlas automáticamente.

Esta feature introduce:
1. **Campo `appVersion`** en `Training` — se rellena con la versión de la app en el momento de guardar.
2. **`migrationService`** — servicio compartido que, al arrancar, detecta trainings sin versión o con versión antigua y aplica las transformaciones necesarias para dejarlos en el formato actual.
3. **Primera migración `undefined → 1.1.0`** — convierte `Impact.magnitude` de escala m/s² a escala raw/16 (multiplica por ~13.06, el factor de conversión entre ambas escalas).

El patrón es extensible: cada futura versión que cambie el modelo de datos añade una función de migración nombrada, y el servicio las encadena automáticamente.

## Criterios de aceptación

- [ ] `Training` tiene el campo `appVersion: string` (semver, ej. `"1.1.0"`)
- [ ] `trainingService.finishTraining()` asigna `appVersion` con la versión actual de la app al crear un Training
- [ ] Existe `shared/services/migration.ts` con `migrationService`
- [ ] `migrationService.migrate(trainings)` devuelve el array con todos los trainings migrados al formato actual
- [ ] Los trainings sin `appVersion` (undefined) se tratan como versión `"1.0.0"`
- [ ] La migración `1.0.0 → 1.1.0` convierte `Impact.magnitude` multiplicando por `RAW16_FACTOR = 13.06` y redondeando a entero
- [ ] Los trainings ya en versión actual (`appVersion === APP_VERSION`) no se tocan
- [ ] `migrationService.migrate()` es idempotente — ejecutarlo dos veces produce el mismo resultado
- [ ] Desktop: las migraciones se ejecutan en el arranque, después de cargar trainings de disco y antes de pasarlos al store; los trainings migrados se reescriben en disco
- [ ] Mobile: ídem, después de `storage.loadTrainings()` y antes de `setTrainings()`
- [ ] Un training migrado tiene `appVersion` actualizada a la versión actual tras la migración

### Constantes

```ts
// shared/constants.ts
export const APP_VERSION = '1.1.0'

// Factor de conversión Impact.magnitude de m/s² a raw/16
// Con MPU-6050 en ±16g: 1g = 2048 LSB raw → /16 = 128 unidades
// 1g = 9.80665 m/s² → factor = 128 / 9.80665 ≈ 13.06
export const RAW16_FACTOR = 13.06
```

### Lógica de negocio

#### migrationService

```ts
// shared/services/migration.ts
import type { Training } from '../types'
import { APP_VERSION, RAW16_FACTOR } from '../constants'

type MigrationFn = (training: Training) => Training

// Registro de migraciones ordenadas: [versión_origen, fn]
// Añadir aquí nuevas migraciones en el futuro
const MIGRATIONS: Array<{ from: string; to: string; fn: MigrationFn }> = [
  {
    from: '1.0.0',
    to:   '1.1.0',
    fn:   migrate_1_0_0_to_1_1_0
  }
]

function migrate_1_0_0_to_1_1_0(training: Training): Training {
  return {
    ...training,
    appVersion: '1.1.0',
    rounds: training.rounds.map((round) => ({
      ...round,
      impacts: round.impacts.map((impact) => ({
        ...impact,
        magnitude: Math.round(impact.magnitude * RAW16_FACTOR)
      }))
    }))
  }
}

export const migrationService = {
  migrate(trainings: Training[]): Training[] {
    return trainings.map((t) => migrationService.migrateOne(t))
  },

  migrateOne(training: Training): Training {
    let current = training
    // Tratar undefined como '1.0.0'
    let version = current.appVersion ?? '1.0.0'

    for (const migration of MIGRATIONS) {
      if (version === migration.from) {
        current = migration.fn(current)
        version = migration.to
      }
    }

    return current
  },

  needsMigration(training: Training): boolean {
    return (training.appVersion ?? '1.0.0') !== APP_VERSION
  }
}
```

#### Ejecutar migraciones al arrancar (Desktop)

En el componente o hook donde se cargan los trainings al iniciar la app:

```ts
import { migrationService } from '@shared/services/migration'
import { invoke } from '@tauri-apps/api/core'

const raw = await invoke<Training[]>('load_trainings')
const migrated = migrationService.migrate(raw)

// Reescribir en disco solo los que cambiaron
migrated
  .filter((t, i) => t.appVersion !== raw[i].appVersion)
  .forEach((t) => invoke('save_training', { training: t }))

setTrainings(migrated)
```

#### Ejecutar migraciones al arrancar (Mobile)

```ts
import { migrationService } from '@shared/services/migration'
import { storage } from '../../services/storage'

const raw = storage.loadTrainings()
const migrated = migrationService.migrate(raw)

migrated
  .filter((t, i) => t.appVersion !== raw[i].appVersion)
  .forEach((t) => storage.saveTraining(t))

setTrainings(migrated)
```

## Escenarios de test

1. **Training legacy (sin appVersion) se migra a 1.1.0**
   - **Given**: training con `appVersion: undefined`, impact con `magnitude: 50`
   - **When**: `migrationService.migrateOne(training)`
   - **Then**: `appVersion === '1.1.0'`, `impact.magnitude === Math.round(50 * 13.06) === 653`

2. **Training ya en versión actual no se modifica**
   - **Given**: training con `appVersion: '1.1.0'`, impact con `magnitude: 847`
   - **When**: `migrationService.migrateOne(training)`
   - **Then**: training idéntico al original (sin cambios)

3. **Idempotencia — migrar dos veces produce el mismo resultado**
   - **Given**: training legacy con `magnitude: 50`
   - **When**: `migrationService.migrateOne(migrationService.migrateOne(training))`
   - **Then**: `magnitude === 653` (igual que migrar una vez)

4. **migrate() procesa un array mixto**
   - **Given**: array con 1 training legacy (`magnitude: 75`) y 1 training `v1.1.0` (`magnitude: 900`)
   - **When**: `migrationService.migrate(trainings)`
   - **Then**: resultado[0].magnitude === `Math.round(75 * 13.06) === 980`; resultado[1].magnitude === `900` (sin tocar)

5. **needsMigration detecta correctamente**
   - **Given**: training con `appVersion: undefined`
   - **When**: `migrationService.needsMigration(training)`
   - **Then**: `true`

6. **Magnitud 0 no rompe la migración**
   - **Given**: training legacy con `magnitude: 0` (golpe sin magnitud)
   - **When**: `migrationService.migrateOne(training)`
   - **Then**: `magnitude === 0` (Math.round(0 * 13.06) = 0)

## Notas de implementación

- `shared/constants.ts` centraliza `APP_VERSION` — es la única fuente de verdad. `package.json` tiene la misma versión pero no se importa en shared para no crear dependencia de plataforma.
- El array `MIGRATIONS` en `migrationService` es la única lista que hay que mantener cuando cambie el modelo de datos en el futuro. Cada migración recibe el training en el formato `from` y devuelve el formato `to`.
- La comparación de versiones es por igualdad de string (`===`), no semver. Las migraciones se encadenan en orden de declaración — si en el futuro hay `1.1.0 → 1.2.0`, un training legacy pasará por ambas automáticamente.
- El factor `RAW16_FACTOR = 13.06` es una aproximación. La conversión no es reversible con precisión total, pero es suficiente para que los datos legacy sean comparables con datos nuevos en la gráfica.
- Si en el futuro se añade migración de perfiles o dispositivos, se puede crear `migrationService.migrateProfiles()` siguiendo el mismo patrón.
