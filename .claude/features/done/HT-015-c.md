## Descripción

Extiende `TrainingSetup` con un configurador de fases que permite al usuario activar/desactivar tres bloques antes de los rounds: **Calentamiento**, **Core** y los **Rounds de saco** (siempre presente). Cuando hay fases físicas activas, el flujo es: WorkoutPlayer(calentamiento) → WorkoutPlayer(core) → sesión de boxeo normal. Los rounds se guardan como `Training` normal; las fases físicas no se persisten. Si el usuario no activa ninguna fase física, el comportamiento es idéntico al actual.

## Criterios de aceptación

- [ ] `TrainingSetup` muestra una sección "Fases de la sesión" con toggles para Calentamiento y Core (Rounds siempre activo y no togglable)
- [ ] Si ninguna fase física está activa, el botón "Iniciar" arranca directamente la sesión de boxeo (comportamiento actual, sin regresión)
- [ ] Si Calentamiento está activo: al pulsar "Iniciar" se muestra `WorkoutPlayer` con la rutina `warmup-boxing` antes de los rounds
- [ ] Si Core está activo: se muestra `WorkoutPlayer` con la rutina `core-boxer` antes de los rounds (después del calentamiento si ambos activos)
- [ ] Al completar las fases físicas, la transición a la sesión de boxeo es automática (sin pantalla intermedia)
- [ ] El usuario puede abortar desde cualquier fase física (`onAbort`) y volver a `TrainingSetup` sin iniciar la sesión de boxeo
- [ ] En Desktop y Mobile el comportamiento es equivalente
- [ ] Los rounds de saco se guardan como `Training` normal (sin cambios en persistencia)
- [ ] La duración estimada en `TrainingSetup` incluye los minutos de las fases físicas activadas

### Tipos nuevos o modificados

No se añaden tipos al dominio. Se añade estado local en `TrainingPage`:

```ts
// Estado interno de TrainingPage (ambas plataformas)
type SessionPhase =
  | 'setup'           // TrainingSetup visible
  | 'warmup'          // WorkoutPlayer con rutina de calentamiento
  | 'core'            // WorkoutPlayer con rutina de core
  | 'boxing'          // Flujo de boxeo actual (preparing/round/resting/finished)

interface PhaseConfig {
  includeWarmup: boolean
  includeCore: boolean
}
```

### Lógica de negocio

#### TrainingSetup — nueva sección de fases

Añadir bajo la configuración de rounds (o encima del botón Iniciar) un bloque "Fases de la sesión":

```
┌──────────────────────────────────────────┐
│ Fases de la sesión                        │
│                                           │
│  🔥 Calentamiento  (8 min)    [toggle]   │
│     Movilidad y activación                │
│                                           │
│  💪 Core           (15 min)   [toggle]   │
│     Abdominales y estabilidad             │
│                                           │
│  🥊 Rounds de saco            [siempre]  │
│     (config de rounds habitual)           │
└──────────────────────────────────────────┘
```

- Los toggles son independientes (se puede activar Core sin Calentamiento).
- "Rounds de saco" no tiene toggle — siempre está activo, solo muestra la config existente.
- La duración estimada actualiza: `durationFisica + durationBoxeo`.
  - `durationFisica = (includeWarmup ? 8 : 0) + (includeCore ? 15 : 0)` minutos.
- `onStart` recibe también `PhaseConfig`:

```ts
// Firma actualizada de onStart en TrainingSetup
onStart: (
  roundDuration: number,
  numRounds: number,
  restDuration: number,
  phases: PhaseConfig
) => void
```

#### TrainingPage — gestión del flujo de fases

Estado nuevo: `sessionPhase: SessionPhase = 'setup'` y `phaseConfig: PhaseConfig`.

```
handleStart(roundDuration, numRounds, restDuration, phases):
  phaseConfig = phases
  si phases.includeWarmup → sessionPhase = 'warmup'
  sino si phases.includeCore → sessionPhase = 'core'
  sino → sessionPhase = 'boxing'; iniciar sesión de boxeo normal

handleWarmupComplete(skipped):
  si phaseConfig.includeCore → sessionPhase = 'core'
  sino → sessionPhase = 'boxing'; iniciar sesión de boxeo normal

handleCoreComplete(skipped):
  sessionPhase = 'boxing'; iniciar sesión de boxeo normal

handlePhysicalAbort():
  sessionPhase = 'setup'   // vuelve al setup, NO inicia boxeo

```

**Render según `sessionPhase`:**

```
'setup'   → <TrainingSetup onStart={handleStart} ... />
'warmup'  → <WorkoutPlayer routine={warmupRoutine} onComplete={handleWarmupComplete} onAbort={handlePhysicalAbort} />
'core'    → <WorkoutPlayer routine={coreRoutine} onComplete={handleCoreComplete} onAbort={handlePhysicalAbort} />
'boxing'  → flujo actual de la TrainingPage (preparing/round/resting/finished)
```

**Iniciar sesión de boxeo** (función interna `startBoxingSession()`):
```ts
reset()
startTraining(connected, profile, roundDuration, numRounds, restDuration)
```
Esta función se llama siempre que `sessionPhase` transiciona a `'boxing'`.

**Invariantes:**
- `sessionPhase = 'boxing'` solo se activa si `connected` está disponible (la validación ya existe en `handleStart`).
- Si el usuario aborta en fase física y el dispositivo se desconecta, al volver a setup lo verá en estado desconectado normalmente.

## Escenarios de test

1. **Escenario**: Sin fases físicas, comportamiento sin regresión
   - **Given**: `includeWarmup=false`, `includeCore=false`
   - **When**: usuario pulsa "Iniciar"
   - **Then**: `sessionPhase` va directamente a `'boxing'`; `startTraining` se llama con los parámetros correctos

2. **Escenario**: Solo calentamiento activo
   - **Given**: `includeWarmup=true`, `includeCore=false`
   - **When**: usuario pulsa "Iniciar"
   - **Then**: `sessionPhase = 'warmup'`; al llamar `onComplete` → `sessionPhase = 'boxing'`

3. **Escenario**: Calentamiento + Core activos
   - **Given**: `includeWarmup=true`, `includeCore=true`
   - **When**: usuario pulsa "Iniciar"
   - **Then**: `warmup` → al completar → `core` → al completar → `boxing`

4. **Escenario**: Abortar durante fase física
   - **Given**: `includeWarmup=true`, usuario en phase `'warmup'`
   - **When**: `onAbort` llamado desde WorkoutPlayer
   - **Then**: `sessionPhase = 'setup'`; `startTraining` NO se ha llamado

5. **Escenario (borde)**: Solo Core (sin calentamiento)
   - **Given**: `includeWarmup=false`, `includeCore=true`
   - **When**: usuario pulsa "Iniciar"
   - **Then**: `sessionPhase` va directamente a `'core'` (salta warmup)

6. **Escenario**: Duración estimada correcta con fases activadas
   - **Given**: `includeWarmup=true`, `includeCore=true`, `numRounds=3`, `roundDuration=180`, `restDuration=60`
   - **When**: se calcula duración total en TrainingSetup
   - **Then**: `8 + 15 + ceil((3×180 + 2×60) / 60)` = 23 + 14 = 37 min aproximados

## Notas de implementación

- Los iconos de las fases deben ser Lucide (no emojis en UI): `Flame` para calentamiento, `Dumbbell` para core, `Target` para rounds.
- Mobile: los toggles usan `Switch` de React Native o el mismo patrón visual que el toggle de "Modo libre" ya existente.
- Desktop: mismo patrón de toggle que el existente en TrainingSetup.
- No se guarda `PhaseConfig` en ningún store — es estado local de sesión. Si el usuario sale y vuelve, los toggles arrancan en `false`.
- Si en el futuro se quiere persistir la preferencia de fases, se añadiría a `AppConfig` (fuera de scope aquí).
