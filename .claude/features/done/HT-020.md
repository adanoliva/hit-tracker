## Descripción

Extiende `TrainingRound` para mostrar el combo del round actual como guía visual estática cuando la sesión proviene de un `WorkoutPlan` con `roundScripts` definidos. Si la sesión es una Sesión libre (sin plan) o el round no tiene script, la pantalla es idéntica a la actual. No hay cambios en la lógica de detección de golpes ni en el guardado.

## Criterios de aceptación

- [x] Cuando el round tiene un combo asociado, se muestra el texto del combo en la pantalla de `TrainingRound`
- [x] El texto del combo es **estático** — no hay interacción, no hay avance automático, no hay validación de si el golpe coincide
- [x] Si el round no tiene combo (sesión libre o round sin script), la pantalla es idéntica a la actual (sin regresión)
- [x] El combo ocupa un área visual diferenciada (caja o banner), no interfiere con el timer ni con el gráfico de golpes
- [x] El texto es legible con fuente monoespaciada grande (el entrenador necesita verlo de lejos)
- [x] Si el combo es largo, hace wrap o scroll horizontal con auto-scroll suave
- [x] La sesión libre (tab Sesión) nunca muestra esta sección

## Requisitos técnicos

### Archivos a modificar

- `src/components/Training/TrainingRound.tsx` — añadir prop `combo?: string` y renderizar el banner si existe
- `src/components/Training/index.tsx` — `TrainingPage` ya no necesita cambios (no recibe combo)
- `src/components/Entrenamiento/PlanRunner.tsx` — pasa el combo del round actual a `TrainingRound` al renderizarlo

### Prop nueva en TrainingRound

```ts
interface TrainingRoundProps {
  // ... props existentes sin cambios ...
  combo?: string  // texto del combo, undefined si no aplica
}
```

### Render del combo

```
Si combo existe:
  ┌──────────────────────────────────┐
  │  Round 1                          │
  │  1 - 2 - 3 - Slip Iz - 3b - 6   │  ← fuente mono, grande, color accent o blanco
  └──────────────────────────────────┘
  [timer y resto de la UI normal abajo]
```

Posición recomendada: **encima del timer**, para ser lo primero que se ve al mirar la pantalla.

### Cómo PlanRunner pasa el combo

```ts
// En PlanRunner, al renderizar la fase boxing:
const script = plan.boxing.roundScripts.find(s => s.round === currentRoundNumber)

// Se pasa como prop al componente de sesión.
// El componente de sesión (TrainingPage embebido en PlanRunner) necesita recibir
// un callback o prop que reenvíe el combo al TrainingRound.
```

**Patrón de implementación**: `PlanRunner` instancia una versión del flujo de boxing que acepta `roundScripts`. La forma más limpia es extraer una función/hook `useCurrentCombo(roundScripts, currentRoundNumber)` que devuelve el combo activo.

## Escenarios de test

1. `combo = "1-2-3-Slip Iz"` → se renderiza en la pantalla (texto visible)
2. `combo = undefined` → no se renderiza ningún banner (pantalla idéntica a actual)
3. `combo = ""` → tratado como undefined (no se muestra banner vacío)

## Notas de implementación

- La pantalla de Sesión libre (`TrainingPage` desde el tab Sesión) nunca pasa `combo`, por lo que nunca mostrará el banner. No se necesita flag especial.
- No hay audio asociado al combo en esta fase.
- Si en el futuro se quiere TTS (text-to-speech de los golpes), se añadiría aquí. Por ahora, solo visual.
