## Descripción

El umbral que determina si un golpe cuenta como "válido" está hardcodeado al 80% del power máximo de la sesión (`intensity >= powerMax * 0.8`) en dos sitios: `calibrationService.isValidHit()` y directamente en `useSensorData.ts` (desktop y mobile). Esta feature añade el campo `validHitThreshold` a `CalibrationProfile` (valor 50–100, por defecto 80) y lo expone como slider en la pantalla de edición de perfil, igual que `threshold` y `sensitivity`.

## Criterios de aceptación

- [x] `CalibrationProfile` tiene el campo `validHitThreshold: number` (entero, 50–100, default 80)
- [x] `calibrationService.createProfile()` asigna `validHitThreshold: 80` por defecto
- [x] `calibrationService.isValidHit()` acepta el perfil completo y usa `profile.validHitThreshold / 100` en lugar de `0.8`
- [x] `useSensorData.ts` (desktop) sustituye `0.8` por `profile.validHitThreshold / 100`
- [x] `useSensorData.ts` (mobile) sustituye `0.8` por `profile.validHitThreshold / 100`
- [x] La pantalla de edición de perfil (desktop) muestra un slider "Umbral golpe válido" con rango 50–100 y paso 5
- [x] La pantalla de edición de perfil (mobile) muestra el mismo slider con los mismos rangos
- [x] Al guardar el perfil editado se persiste `validHitThreshold`
- [x] Los perfiles existentes sin el campo (datos guardados previamente) funcionan con valor 80 por defecto (backward compat)

### Tipos nuevos o modificados

```ts
// shared/types/index.ts
export interface CalibrationProfile {
  id: string
  name: string
  threshold: number
  sensitivity: number
  validHitThreshold: number   // nuevo — porcentaje 50-100, default 80
  calibrationData?: CalibrationData
  createdAt: number
}
```

### Lógica de negocio

**`calibrationService.isValidHit`** — firma actual recibe `(impact, powerMax)`. Cambiar a recibir también el perfil:

```ts
isValidHit(impact: Impact, powerMax: number, profile: CalibrationProfile): boolean {
  return impact.intensity >= powerMax * (profile.validHitThreshold / 100)
}
```

Si se prefiere no cambiar la firma pública, se puede pasar el ratio directamente:

```ts
isValidHit(impact: Impact, powerMax: number, validRatio: number): boolean {
  return impact.intensity >= powerMax * validRatio
}
// llamada: calibrationService.isValidHit(impact, powerMax, profile.validHitThreshold / 100)
```

Elegir la segunda opción para mantener la función sin dependencia de tipos concretos.

**`useSensorData.ts`** (desktop y mobile) — la línea:
```ts
isValid: intensity >= newPowerMax * 0.8
```
pasa a:
```ts
isValid: intensity >= newPowerMax * (profile.validHitThreshold / 100)
```
`profile` ya está disponible en ambos hooks como parámetro/prop.

**Backward compat** — al leer perfiles persistidos, si `validHitThreshold` es `undefined`, tratarlo como 80. Hacerlo en el store o en el selector, no en el hook:

```ts
// profileStore o selector
const safeProfile = { validHitThreshold: 80, ...profile }
```

**Slider en Profiles (desktop)** — añadir entre el slider de `sensitivity` y los botones Guardar/Cancelar:

```tsx
<SliderField
  label="Umbral golpe válido"
  hint="Porcentaje del golpe más fuerte de la sesión a partir del cual un golpe cuenta como válido. 80% = solo los 2 últimos deciles cuentan. Bájalo si quieres que cuenten más golpes."
  value={editing.validHitThreshold}
  min={50}
  max={100}
  step={5}
  unit="%"
  color="text-text-primary"
  onChange={(v) => setEditing({ ...editing, validHitThreshold: v })}
/>
```

`handleSaveEdit` debe incluir `validHitThreshold: editing.validHitThreshold` junto a `threshold` y `sensitivity`.

La vista resumida del perfil (modo no-edición) puede mostrar el valor solo si difiere de 80:
```
Detección 15 · Potencia 25 · Válido ≥70%
```
O simplemente mostrarlo siempre junto a los otros dos parámetros. Decisión de implementador — ambas son válidas.

## Escenarios de test

1. **Umbral personalizado marca hits correctamente**
   - **Given**: perfil con `validHitThreshold: 70`; sesión con `powerMax = 100`
   - **When**: llega un impacto con `intensity = 72`
   - **Then**: `isValid = true` (72 >= 100 * 0.70)

2. **Umbral por defecto (80) mantiene comportamiento actual**
   - **Given**: perfil con `validHitThreshold: 80`; sesión con `powerMax = 100`
   - **When**: llega un impacto con `intensity = 78`
   - **Then**: `isValid = false` (78 < 100 * 0.80)

3. **Perfil sin campo (datos legacy) usa 80 por defecto**
   - **Given**: perfil cargado de disco sin campo `validHitThreshold` (undefined)
   - **When**: se usa en `useSensorData`
   - **Then**: no hay crash; `isValid` se calcula con ratio 0.80

4. **Guardar y recargar perfil persiste el umbral**
   - **Given**: usuario edita perfil y pone `validHitThreshold = 60`
   - **When**: guarda, recarga la app, abre el perfil en edición
   - **Then**: el slider muestra 60

## Notas de implementación

- El campo se llama `validHitThreshold` (entero 50–100) y no `validHitRatio` para que el usuario lo entienda si alguna vez se expone en JSON exportado.
- El store `profileStore` persistido en disco puede tener perfiles sin este campo — el spread con default `{ validHitThreshold: 80, ...storedProfile }` en la hidratación del store es suficiente.
- No tocar `TrainingRound.tsx` (desktop) ni equivalentes — ya leen `i.isValid` del impacto grabado; el campo queda fijo en el momento de la sesión.
