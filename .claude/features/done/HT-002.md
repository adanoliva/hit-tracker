## Descripción

Al pulsar sobre una sesión en el historial del Dashboard, se abre una pantalla de detalle que muestra el desglose por round con un gráfico de puntos (scatter) donde el eje X es el tiempo dentro del round y el eje Y es la intensidad del golpe. El usuario puede navegar entre rounds mediante tabs. Desde esta pantalla puede volver al Dashboard o eliminar la sesión (con confirmación).

## Criterios de aceptación

- [ ] Pulsar sobre cualquier sesión del historial navega a la pantalla de detalle de esa sesión
- [ ] La pantalla muestra un header con los datos globales de la sesión (fecha, device, rounds, golpes totales, power máx, HPM promedio)
- [ ] Hay tabs "R1", "R2", "R3"... (tantas como rounds tenga la sesión) para navegar entre rounds
- [ ] El round seleccionado muestra sus stats encima del gráfico: golpes totales, golpes válidos, power máx, HPM promedio, duración del round
- [ ] El gráfico muestra un punto por cada `Impact` del round: eje X = tiempo relativo al inicio del round (segundos), eje Y = `impact.intensity` (0–100)
- [ ] Los puntos con `impact.isValid = true` se muestran en color acento; los inválidos en color gris/apagado
- [ ] El gráfico tiene ejes etiquetados: X en segundos, Y en intensidad (0–100)
- [ ] Si un round no tiene ningún golpe (`impacts.length === 0`), se muestra mensaje "Sin golpes registrados en este round"
- [ ] Botón "Volver" regresa al Dashboard sin modificar nada
- [ ] Botón "Eliminar sesión" abre un diálogo de confirmación antes de borrar
- [ ] Confirmar eliminación borra la sesión, navega al Dashboard y la sesión desaparece de la lista
- [ ] Cancelar eliminación cierra el diálogo sin cambios
- [ ] La pantalla es solo lectura: no hay controles de edición

### Lógica de negocio

#### Cálculo del eje X (tiempo relativo)
Cada `Impact` tiene `impact.time` (timestamp absoluto en ms). El eje X se normaliza restando `round.startTime`:

```ts
const relativeTimeSeconds = (impact.time - round.startTime) / 1000
```

El dominio del eje X va de `0` a `(round.endTime - round.startTime) / 1000` segundos.

#### Cálculo del eje Y
Directamente `impact.intensity` (valor 0–100, ya calculado en `calibrationService`).

#### Tabs de rounds
- Generadas dinámicamente: `training.rounds.map((r, i) => ({ label: \`R${r.number}\`, index: i }))`
- Estado local `selectedRoundIndex: number` (inicializado a `0`)
- Si la sesión tiene un solo round, se muestra igualmente el tab (sin opción de navegar)

#### Stats del round seleccionado
Extraídas de `round.stats` (tipo `RoundStats`):
- Duración: `round.stats.duration` ms → convertir a `mm:ss`
- Golpes totales: `round.stats.totalImpacts`
- Golpes válidos: `round.stats.validHits`
- Power máx: `round.stats.powerMax`
- HPM promedio: `round.stats.hpmAverage`

#### Eliminación
1. Mostrar diálogo de confirmación: "¿Eliminar esta sesión? Esta acción no se puede deshacer."
2. Si confirma → llamar `trainingStore.deleteTraining(training.id)` → llamar `onDelete(training.id)` → navegar al Dashboard
3. Si cancela → cerrar diálogo, no hacer nada

#### Navegación Desktop
App.tsx ya gestiona qué componente renderizar. Añadir estado:
```ts
const [selectedTraining, setSelectedTraining] = useState<Training | null>(null)
```
- Si `selectedTraining !== null` → renderizar `<SessionDetail>`
- Si `null` → renderizar vista normal del Dashboard

#### Navegación Mobile
Usar el stack navigator existente de React Navigation. Añadir screen `SessionDetail` que recibe `training` como param de navegación:
```ts
navigation.navigate('SessionDetail', { trainingId: training.id })
// En SessionDetail, recuperar training del store por ID
```

## Escenarios de test

1. **Escenario**: Calcular tiempo relativo de impacts en el gráfico
   - **Given**: Un round con `startTime = 1000000` y dos impacts con `time = 1005000` y `time = 1015000`
   - **When**: Se calcula `relativeTimeSeconds` para cada impact
   - **Then**: Los valores son `5.0` y `15.0` segundos respectivamente

2. **Escenario**: Round sin golpes
   - **Given**: Un `Round` con `impacts = []`
   - **When**: Se renderiza el tab de ese round
   - **Then**: No se intenta renderizar el gráfico y se muestra el mensaje "Sin golpes registrados en este round"

3. **Escenario**: Eliminación cancelada no modifica el store
   - **Given**: El store tiene 3 trainings; el usuario está en el detalle del training con id "abc"
   - **When**: Pulsa "Eliminar sesión" y luego "Cancelar" en el diálogo
   - **Then**: `trainingStore.deleteTraining` no es llamado y el store sigue teniendo 3 trainings

4. **Escenario**: Eliminación confirmada elimina del store y navega atrás
   - **Given**: El store tiene 3 trainings; el usuario confirma la eliminación del training "abc"
   - **When**: Se ejecuta `trainingStore.deleteTraining("abc")`
   - **Then**: El store pasa a tener 2 trainings, y se invoca `onDelete("abc")`

5. **Escenario**: Sesión con un solo round
   - **Given**: Un Training con `rounds.length === 1`
   - **When**: Se abre la pantalla de detalle
   - **Then**: Se muestra exactamente un tab "R1" y el gráfico del único round

## Notas de implementación

- **Gráfico en Desktop**: usar SVG nativo (igual que el gráfico de progresión del Dashboard). No añadir dependencias nuevas.
- **Gráfico en Mobile**: usar SVG con `react-native-svg` (ya instalado para el gráfico del Dashboard mobile).
- **Puntos del scatter**: radio fijo (~4–6px desktop, ~5–7 mobile). Color: `colors.accent` para válidos, `colors.textSecondary` (o similar apagado) para inválidos. En desktop usar los colores Tailwind ya en uso.
- **Escala Y**: siempre de 0 a 100 (dominio fijo de intensidad), no auto-escalar, para que rondas distintas sean comparables visualmente.
- **Escala X**: auto — usar la duración real del round como máximo del eje.
- **Eliminar desde detalle vs desde lista**: el botón de eliminar que ya existe en el Dashboard (en la lista) debe mantenerse; esta feature añade una segunda vía de eliminación desde el detalle.
- **Mobile navigation**: si MobileLayout usa `BottomTabNavigator`, crear un `Stack.Navigator` que envuelva el tab de Dashboard para permitir push a `SessionDetail` sin perder la tab bar, o usar un modal screen a nivel raíz.
