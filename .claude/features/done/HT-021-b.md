## Descripción

Permite buscar ejercicios en la API pública de wger (https://wger.de/api/v2/) y añadirlos al catálogo local. Solo aplica a las categorías Calentamiento y Core/Fullbody. El filtro de equipamiento limita los resultados a ejercicios sin material o con equipamiento básico doméstico. Los ejercicios importados se guardan localmente y se usan igual que los del catálogo base.

## Criterios de aceptación

- [x] Buscador de texto que consulta la API wger al pulsar "Buscar" (no en tiempo real)
- [x] Los resultados muestran: nombre, músculos principales, equipamiento requerido
- [x] Filtro activo por defecto: solo equipamiento `none` y `dumbbell` (sin barra, máquinas, etc.)
- [x] Botón "Añadir" en cada resultado importa el ejercicio al catálogo local
- [x] Los ejercicios ya importados muestran "Añadido" (no se duplican)
- [x] Si la red no está disponible, muestra error amigable sin crashear
- [x] La búsqueda devuelve resultados en español si está disponible, inglés como fallback
- [x] Máximo 20 resultados por búsqueda (paginación básica: botón "Ver más")

## Requisitos técnicos

### API wger

Endpoint: `GET https://wger.de/api/v2/exercise/?format=json&language=2&category=X&equipment=Y`

Parámetros clave:
- `language`: 2 = inglés, 4 = alemán, 6 = español — buscar primero en 6, fallback a 2
- `category`: 10 = Abs, 8 = Arms, 12 = Back, 14 = Calves, 11 = Chest, 9 = Legs, 13 = Shoulders — mapear a nuestras categorías
- `equipment`: 7 = Body weight, 3 = Dumbbell (los únicos aceptados)

Mapeo de categorías wger → nuestra categoría:
| wger category | Nuestra categoría |
|---|---|
| Abs (10) | core |
| Back (12) | core |
| Shoulders (13) | upper |
| Arms (8) | upper |
| Legs (9) | lower |
| Chest (11) | fullbody |

### Archivos a crear

- `src/core/services/wgerService.ts` — funciones de búsqueda e importación
- `src/components/Entrenamiento/WgerSearchScreen.tsx` — pantalla de búsqueda (modal o stack screen)

### wgerService

```ts
interface WgerExercise {
  id: number
  name: string
  description: string  // puede contener HTML — sanitizar
  category: { id: number; name: string }
  equipment: Array<{ id: number; name: string }>
  muscles: Array<{ name_en: string }>
}

async function searchExercises(query: string, language?: number): Promise<WgerExercise[]>
function mapToExercise(wger: WgerExercise): Omit<Exercise, 'id'>
```

- `mapToExercise` convierte el formato wger a nuestro `Exercise`.
- La descripción de wger puede tener HTML; usar regex simple para strip de tags (no añadir librería).
- `rest` por defecto: 30s. `difficulty`: siempre `'medium'` (wger no tiene este campo).
- El ID del ejercicio importado será `wger-${wger.id}`.

### Persistencia

Los ejercicios importados de wger se guardan en `custom_exercises.json` junto con los custom de boxing (mismo store que HT-021-a).

### Manejo de errores

- Timeout de 10s en fetch; si falla → toast "Sin conexión, inténtalo más tarde"
- Rate limiting de wger: máximo 1 búsqueda cada 2s (debounce en el botón)

## Notas de implementación

- La API de wger es pública, no requiere autenticación para lectura.
- Solo se hace fetch cuando el usuario pulsa "Buscar", nunca en background.
- No cachear respuestas de wger (el catálogo local ya es el "cache" definitivo una vez importado).
- Sanitización de HTML de la descripción: `description.replace(/<[^>]*>/g, '').trim()` es suficiente.
- El filtro de equipamiento (`7,3`) se incluye siempre; no es configurable por el usuario en v1.
