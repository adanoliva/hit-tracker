## Descripción

Implementa la pantalla principal del tab "Entrenamiento": lista de planes guardados con opción de ejecutar, editar o eliminar cada uno, y botón para crear uno nuevo. Al ejecutar un plan, orquesta el flujo completo: WorkoutPlayer(calentamiento) → WorkoutPlayer(core) → Sesión de boxing, guardando la sesión de boxing en el historial al terminar.

## Criterios de aceptación

- [ ] Lista de planes (`WorkoutPlan[]`) vacía muestra call-to-action "Crea tu primer entrenamiento"
- [ ] Cada plan muestra: nombre, resumen de fases activas (iconos), duración estimada total
- [ ] Swipe-to-delete o botón de eliminar con confirmación
- [ ] Botón/FAB "Nuevo entrenamiento" navega al builder (HT-019-b)
- [ ] Botón de catálogo de ejercicios navega a HT-021-a
- [ ] Al pulsar "Ejecutar" en un plan: flujo warmup → core → boxing según las fases activas
- [ ] Si un plan no tiene ejercicios de calentamiento (`warmupExerciseIds.empty`), esa fase se salta
- [ ] Si un plan no tiene ejercicios de core (`coreExerciseIds.empty`), esa fase se salta
- [ ] La sesión de boxing al terminar se guarda en el historial (mismo `addTraining` del store)
- [ ] La pantalla de round durante la ejecución de un plan muestra el script del round si existe (pasa el combo al componente — ver HT-020)
- [ ] Al abortar desde cualquier fase física, vuelve a la lista sin iniciar boxing
- [ ] Al abortar la sesión de boxing, vuelve a la lista (mismo comportamiento que Sesión actual)

## Requisitos técnicos

### Archivos a crear / modificar

- `src/components/Entrenamiento/index.tsx` — reemplaza el placeholder de HT-017; pantalla principal
- `src/components/Entrenamiento/PlanCard.tsx` — tarjeta de plan en la lista
- `src/components/Entrenamiento/PlanRunner.tsx` — orquestador del flujo de ejecución (warmup→core→boxing)

### Lógica de ejecución (PlanRunner)

```
Estado: phase: 'warmup' | 'core' | 'boxing'

Al iniciar plan:
  si warmupExerciseIds.length > 0 → phase = 'warmup'
  sino si coreExerciseIds.length > 0 → phase = 'core'
  sino → phase = 'boxing'

handleWarmupComplete → si coreExerciseIds.length > 0 → phase = 'core' sino 'boxing'
handleCoreComplete → phase = 'boxing'
handlePhysicalAbort → onAbort() (vuelve a lista)
handleBoxingEnd(training) → addTraining(training); onDone()
```

El `PlanRunner` recibe `plan: WorkoutPlan` y callbacks `onDone`, `onAbort`.

Pasa `roundScripts` al componente de sesión de boxing para que muestre combos (HT-020).

### Duración estimada en PlanCard

```
warmupMins = warmupExercises.reduce(total tiempo) / 60
coreMins   = coreExercises.reduce(total tiempo) / 60
boxingMins = ceil((numRounds × roundDuration + (numRounds-1) × restDuration) / 60)
total = warmupMins + coreMins + boxingMins
```

Si `exerciseService` no está disponible (ejercicios no resueltos), mostrar solo boxing.

### WorkoutPlayer para calentamiento/core

Reutiliza `WorkoutPlayer` de HT-015-b con las rutinas construidas dinámicamente desde los `exerciseIds` del plan:

```ts
// Construir ResolvedRoutine desde los IDs del plan
function buildRoutine(ids: string[], name: string, category: ExerciseCategory): ResolvedRoutine {
  const resolvedExercises = ids.map(id => exerciseService.getById(id)).filter(Boolean) as Exercise[]
  return { id: 'dynamic', name, category, durationMin: 0, difficulty: 'medium', exercises: ids.map(id => ({ exerciseId: id })), resolvedExercises }
}
```

## Escenarios de test (lógica pura)

1. Plan con todas las fases → ejecuta warmup → core → boxing en orden
2. Plan sin warmup → salta directamente a core → boxing
3. Plan sin warmup ni core → va directo a boxing
4. Abortar en fase warmup → no llega a boxing, no guarda sesión

## Notas de implementación

- `PlanRunner` es un componente puramente orquestador; no tiene UI propia, renderiza el componente de la fase activa.
- La sesión de boxing dentro de un plan usa el mismo `TrainingRound`/`TrainingRest` existente — sin duplicar código.
- El paso de `roundScripts` al componente de boxing es el único cambio en la capa de sesión (HT-020).
