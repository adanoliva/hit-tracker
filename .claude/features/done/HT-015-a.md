## Descripción

Crea la capa de datos para el módulo de entrenamiento físico: tipos TypeScript compartidos, un catálogo JSON local con ~30 ejercicios curados en español para boxeadores (calentamiento, core, fullbody), y un `exerciseService` que los expone. Es la base que HT-015-b y HT-015-c necesitan. No hay UI en esta fase.

## Criterios de aceptación

- [ ] Los tipos `Exercise`, `Routine` y `RoutineExercise` están definidos en `shared/types/index.ts`
- [ ] El archivo `shared/data/exercises.json` contiene ≥ 25 ejercicios con los campos requeridos
- [ ] El archivo `shared/data/routines.json` contiene las 3 rutinas base: Calentamiento Boxeo, Core Boxeador, Fullbody Sin Material
- [ ] `exerciseService.getRoutines()` devuelve las rutinas con sus ejercicios populados
- [ ] `exerciseService.getByCategory(cat)` filtra ejercicios por categoría
- [ ] Los re-exports de Desktop y Mobile apuntan a `@shared`
- [ ] El catálogo funciona sin conexión a internet

### Tipos nuevos o modificados

```ts
// shared/types/index.ts

export type ExerciseCategory = 'warmup' | 'core' | 'upper' | 'lower' | 'fullbody' | 'mobility'

export interface Exercise {
  id: string                   // slug único, ej: "plank-isometric"
  name: string                 // "Plancha isométrica"
  category: ExerciseCategory
  muscles: string[]            // ["Core", "Abdominales"]
  equipment: 'none' | 'dumbbells' | 'pull-up-bar'
  description: string          // 2-3 frases de instrucción
  imageUrl?: string            // URL local asset o remota cacheada (opcional)
  duration?: number            // segundos (para ejercicios de tiempo)
  reps?: number                // repeticiones (alternativo a duration)
  rest: number                 // segundos de descanso TRAS el ejercicio
  difficulty: 'easy' | 'medium' | 'hard'
}

export interface RoutineExercise {
  exerciseId: string           // referencia al Exercise.id
  sets?: number                // si aplica (default: 1)
  reps?: number                // override del Exercise.reps
  duration?: number            // override del Exercise.duration
}

export interface Routine {
  id: string
  name: string                 // "Calentamiento Boxeo"
  category: ExerciseCategory   // categoría dominante de la rutina
  durationMin: number          // duración estimada en minutos
  exercises: RoutineExercise[]
  difficulty: 'easy' | 'medium' | 'hard'
}
```

### Lógica de negocio

**`exerciseService`** es un singleton que carga el catálogo en memoria al importarse:

```ts
class ExerciseService {
  private exercises: Exercise[]   // cargados del JSON
  private routines: Routine[]     // cargadas del JSON

  getAll(): Exercise[]
  getByCategory(cat: ExerciseCategory): Exercise[]
  getById(id: string): Exercise | undefined
  getRoutines(): Array<Routine & { resolvedExercises: Exercise[] }>
  getRoutineById(id: string): (Routine & { resolvedExercises: Exercise[] }) | undefined
}
```

`getRoutines()` popula cada `RoutineExercise.exerciseId` con el `Exercise` completo del catálogo. Si un `exerciseId` no existe en el catálogo, lo omite (no rompe).

## Escenarios de test

1. **Escenario**: Catálogo carga correctamente
   - **Given**: `exerciseService` importado
   - **When**: se llama `exerciseService.getAll()`
   - **Then**: devuelve ≥ 25 ejercicios, todos con `id`, `name`, `category`, `rest` definidos

2. **Escenario**: Rutina popula ejercicios correctamente
   - **Given**: catálogo cargado
   - **When**: `exerciseService.getRoutineById('warmup-boxing')`
   - **Then**: `resolvedExercises` tiene exactamente 8 ejercicios en el mismo orden que `exercises[]`

3. **Escenario (borde)**: exerciseId inválido en rutina
   - **Given**: `routines.json` con una entrada `{ "exerciseId": "no-existe" }`
   - **When**: `getRoutines()`
   - **Then**: ese ejercicio se omite, el resto de la rutina se devuelve correctamente sin lanzar error

4. **Escenario**: Filtrado por categoría
   - **Given**: catálogo cargado
   - **When**: `exerciseService.getByCategory('warmup')`
   - **Then**: todos los resultados tienen `category === 'warmup'`; hay ≥ 8

## Notas de implementación

- El JSON se importa estáticamente (`import exercises from '../data/exercises.json'`) — sin fetch en runtime.
- No hay persistencia ni sync wger en esta fase. El sync wger es una mejora futura (post HT-015-c).
- Los campos `duration` y `reps` son mutuamente excluyentes por ejercicio, pero el tipo los permite opcionales para máxima flexibilidad.
- En `RoutineExercise`, los campos `reps`/`duration`/`sets` son overrides que tienen precedencia sobre el `Exercise` base cuando el WorkoutPlayer los usa.
